# Boundary: Codex runtime

Where Codex is on this machine, for the terminal, the dispatch helper and native mode alike: one search order, one cache, claude-runtime's Windows PATH merge, and the npm layouts K0b captured (`tests/fixtures/real-cli/codex-layouts.json`). Main keeps one locator: native mode, the account reads and the usage inputs run its `file`, a local terminal is told its `path` in `AGENTRIX_CODEX_EXECUTABLE`, the dispatch helper resolves that path to the same file, and Settings › Agents reads its last result.

## Owns
- `electron/features/codex-runtime/**`

## Interface
- `createCodexLocator` (`electron/features/codex-runtime/locator.cjs`) — `{ locate, refresh, peek }` over injected `probe`, `files`, `storedPath`, `readNpmPrefix` and `now`. `locate({ env, platform, arch, home, prefer })` and `refresh(…, { throttled })` give `{ file, path, fileShown, version, via, fingerprint: { file, size, mtimeMs, pathHash }, reason, searched, pathFolders }`: `file` is the real program, `path` what a terminal is told (the shim the wrapper takes, or the program or link itself), `fileShown` the file with home (from the environment) as `~`, `version` null when `--version` printed none, `reason` a `codex.*` Reason (`timeout`, `failed`, `unreadable` beside a found file; `not_found` with `pathFolders` and `searched`, or `incomplete` with the package, when none was found). Search order: `prefer` (a file the helper was told), then the effective PATH (inherited, then the stored Windows PATH merged by claude-runtime's `mergePath`), each folder in the wrapper's order (codex.ps1, each PATHEXT, bare codex; a shim that comes first puts its npm packages before codex.exe), then npm's global prefix (NPM_CONFIG_PREFIX, the user's .npmrc, %APPDATA%\npm; read, never run), the official installer and WinGet's links and packages on Windows, the system folders elsewhere. An npm package's program is its nested platform package, the hoisted one beside it, its own vendor folder, then 0.46's `vendor/<triple>/codex/codex.exe`, this machine's CPU first; a package behind a link (pnpm's store, nvm-windows' junction) is looked at where it really is, which stays inside where its folder really is and is never a UNC path; a package whose program no layout names is looked for in each of its layouts' `vendor/<triple>` folders, at most three folders below, under the same confinement and with that layout's `via`, before it is called incomplete. The first runnable file found is the answer. A refresh reads the stored Windows PATH and searches; a throttled one does that at most once a minute; a locate keeps the last answer while its `path` still leads where it led (on Windows in any letter case) and the file keeps its size and mtime, with or without a version; nothing found until the next refresh. A check that printed no version is run again only by a search a refresh started (an explicit one, or a throttled one past its minute). Overlapping calls share one search. `peek()` is the last result, null before the first search
- `VIAS` (`electron/features/codex-runtime/locator.cjs`) — every `via`: `path` (an inherited PATH folder's codex.exe), `npm-shim` (a package a shim names elsewhere than its folder's own node_modules: a project's node_modules\.bin, pnpm), `npm-vendor` (the package's program inside it: the nested platform package or 0.46's single package), `npm-hoisted` (the platform package beside the main one), `npm-prefix` (npm's global prefix found off PATH), `registry-path` (a folder only the stored Windows PATH has), `official-installer` (%LOCALAPPDATA%\Programs\OpenAI\Codex\bin), `winget` (WinGet's links and packages), `system` (/opt/homebrew/bin, /usr/local/bin, /usr/bin)
- `processLocator` (`electron/features/codex-runtime/locator.cjs`) — the locator of a process that has no host to inject one: the dispatch helper
- `codexExecutable` (`electron/features/codex-runtime/locator.cjs`) — `(env, platform) → file | null` through `processLocator`; the codex-app-server runtime's default resolver
- `packageBinaries` (`electron/features/codex-runtime/locator.cjs`) — the npm layout table above, `(packageDir, arch, path) → [file, layout][]`, which the terminal probes' `resolveCli` (scripts/codex-cli-resolution.cjs) shares

## Invariants
- Every install way is found in the wrapper's order with one of the `via` names the shared type and the settings' words also list, no other product code looks for Codex's layouts, a shim's package stays in its folder, where links really take it too, a package whose program moved to an unknown layout is still found in its vendor tree, and none found says where it looked with home as ~ — the owner's Codex sits off C: in layouts the old PATH scan missed — test: `tests/codex-runtime-locator.test.cjs` › "Windows: Codex is found through a codex.cmd shim, a nested or hoisted npm package, an npm prefix on another drive, the stored PATH, the official installer and WinGet; none found says where it looked"; test: `tests/codex-runtime-locator.test.cjs` › "POSIX: Codex is found on PATH, in npm's prefix bin and the system folders, in the platform path rules on any host"; test: `tests/codex-runtime-locator.test.cjs` › "a package a link takes out of its folder or to a network share is never run; a junction that moves both is followed"; test: `tests/codex-runtime-locator.test.cjs` › "a package whose program moved to a layout no table knows is found in its vendor tree, within bounds and its folder"; test: `tests/codex-runtime-guards.test.cjs` › "every way Codex can be found is in the locator, the shared type and the words, and nowhere else"
- One fingerprint runs `--version` once; a changed file or PATH searches again, the same file reached through another letter case or a junction does not — test: `tests/codex-runtime-locator.test.cjs` › "one fingerprint runs --version once"; test: `tests/codex-runtime-locator.test.cjs` › "a locate keeps the answer when PATH spells its folder in another case or reaches it through a junction"
- Codex has no minimum version: one whose check prints no version is still the answer and is run, with the check's reason, which a locate keeps however long and only a refresh runs again, so a hanging Codex gains no process from main's reads — test: `tests/codex-runtime-locator.test.cjs` › "a Codex that prints no version is still found and used, with why"
- The terminal, the dispatch helper and native mode run the same file: main tells a local terminal where it was found, the helper resolves that to the same program, and an SSH project's terminal is never told this machine's Codex — test: `tests/codex-runtime-locator.test.cjs` › "the terminal, the helper and native mode get the same file"; test: `tests/codex-runtime-locator.test.cjs` › "an SSH terminal is never told this machine's Codex"
- A terminal's codex is the user's alias, then the file Agentrix chose while it exists, then the wrapper's own search — test: `tests/codex-runtime-locator.test.cjs` › "wrapper runs the Codex Agentrix chose while it exists, and otherwise the first on PATH"; test: `tests/codex-runtime-locator.test.cjs` › "PowerShell wrapper runs the Codex Agentrix chose while it exists, and otherwise the first codex on PATH"
- A folder holding SHIM_MARKER is never searched, even for a file the helper was told — a shim there would run the dispatcher, not Codex — test: `tests/codex-runtime-guards.test.cjs` › "the Agentrix shim folder is never a locator candidate, for Claude or Codex"
- The locator and what it requires travel with the dispatch helper within the SSH worker's limits — test: `tests/boundary-dispatch.test.cjs` › "the helper's runtime modules require only Node built-ins and each other"; test: `tests/boundary-dispatch.test.cjs` › "the helper and its runtime modules fit the SSH worker limits with a quarter to spare, and the open message fits its line"
