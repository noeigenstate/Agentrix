# Boundary: Codex runtime

Where Codex is on this machine, for the terminal, the dispatch helper and native mode alike: one search order, one cache, claude-runtime's Windows PATH merge, and the npm layouts K0b captured (`tests/fixtures/real-cli/codex-layouts.json`). Main keeps one locator: native mode, the account reads and the usage inputs run its `file`, a local terminal is told its `path` in `AGENTRIX_CODEX_EXECUTABLE`, the dispatch helper resolves that path to the same file, and Settings › Agents reads its last result. When the fast search finds nothing on Windows, main's locator scans the local drives in the background (drive-scan.cjs) and keeps a hit for the next start.

## Owns
- `electron/features/codex-runtime/**`

## Interface
- `createCodexLocator` (`electron/features/codex-runtime/locator.cjs`) — `{ locate, refresh, peek }` over injected `probe`, `files`, `storedPath`, `registry`, `readNpmPrefix` and `now`, and main's `scan` (a walk of the local drives), `store` (`read`/`write` of the kept hit) and `changed` (told when a background scan changed the answer); a locator without `scan` never scans. `locate({ env, platform, arch, home, prefer })` and `refresh(…, { throttled })` give `{ file, path, fileShown, version, via, fingerprint: { file, size, mtimeMs, pathHash }, reason, searched, pathFolders }`, and a not-found answer `scan` (`running` while the drives are searched, `done` once they were): `file` is the real program, `path` what a terminal is told (the shim the wrapper takes, or the program or link itself), `fileShown` the file with home (from the environment) as `~`, `version` null when `--version` printed none, `reason` a `codex.*` Reason (`timeout`, `failed`, `unreadable` beside a found file; `not_found` with `pathFolders` and `searched`, or `incomplete` with the package, when none was found). Search order: `prefer` (a file the helper was told), then the effective PATH (inherited, then the stored Windows PATH merged by claude-runtime's `mergePath`), each folder in the wrapper's order (codex.ps1, each PATHEXT, bare codex; a shim that comes first puts its npm packages before codex.exe), then npm's global prefix (NPM_CONFIG_PREFIX, the user's .npmrc, %APPDATA%\npm; read, never run), the official installer and WinGet's links and packages on Windows, then the other installers' folders that are there (only those join `searched`): Scoop's `apps\codex\current` and `shims` (SCOOP or ~\scoop, then SCOOP_GLOBAL or %ProgramData%\scoop), Chocolatey's bin (%ChocolateyInstall%, default %ProgramData%\chocolatey), Volta's bin (%VOLTA_HOME%, default %LOCALAPPDATA%\Volta), Bun's ~\.bun\bin and ~\.bun\install\global, pnpm's PNPM_HOME (default %LOCALAPPDATA%\pnpm), Yarn's %LOCALAPPDATA%\Yarn\bin and Yarn\Data\global, nvm-windows' NVM_SYMLINK then each NVM_HOME version, fnm's FNM_DIR (default %APPDATA%\fnm) node-versions\<v>\installation, the codex.exe the OpenAI extension (openai.chatgpt-*) of VS Code, VS Code Insiders, Cursor and Windsurf bundles in bin\windows-*, versions newest first and this CPU first, then what the registry names (`registry`, read by a full search through the environment's own PowerShell, never written: App Paths' codex.exe, user then machine, and the InstallLocation, and its bin, of each Uninstall entry whose DisplayName mentions Codex); elsewhere the system folders. Only npm's layouts are captured (codex-layouts.json); the other installers' folders follow each tool's documented convention and are unconfirmed, so each is bounded to a fixed folder, one version listing or one bin level, and a wrong one costs a listing. An npm package's program is its nested platform package, the hoisted one beside it, its own vendor folder, then 0.46's `vendor/<triple>/codex/codex.exe`, this machine's CPU first; a package behind a link (pnpm's store, nvm-windows' junction, npm's globals moved to another drive, `npm link`) is looked at where it really is, anywhere on this machine but on a share only when its folder really is on that same share (a mapped drive), and one passed over for that is not incomplete either; a package whose program no layout names is looked for in each of its layouts' `vendor/<triple>` folders, at most three folders below, under the same share rule and with that layout's `via`, before it is called incomplete. `searched` names each place once. The first runnable file found is the answer. A refresh reads the stored Windows PATH and searches; a throttled one does that at most once a minute; a locate keeps the last answer while its `path` still leads where it led (on Windows in any letter case) and the file keeps its size and mtime, with or without a version; nothing found until the next refresh. Nothing found on Windows: the kept hit is tried while its file keeps its size and mtime (otherwise it is dropped), then, with `scan`, a background scan starts when none runs and none ran yet, for an explicit refresh, or for a full search an hour after the last; its hits run through the same folder search with via `drive-scan`, and the first that runs becomes the answer, is kept, and `changed` is told, while nothing else was found meanwhile. No scan on POSIX. A check that printed no version is run again only by a search a refresh started (an explicit one, or a throttled one past its minute). Overlapping calls share one search. `peek()` is the last result; a search that chose another file or path than that result names says so at once, with `version` and `reason` null, while its `--version` runs (a result for the same file keeps its own until the check settles); null before the first search
- `VIAS` (`electron/features/codex-runtime/locator.cjs`) — every `via`: `path` (an inherited PATH folder's codex.exe), `npm-shim` (a package a shim names elsewhere than its folder's own node_modules: a project's node_modules\.bin, pnpm), `npm-vendor` (the package's program inside it: the nested platform package or 0.46's single package), `npm-hoisted` (the platform package beside the main one), `npm-prefix` (npm's global prefix found off PATH), `registry-path` (a folder only the stored Windows PATH has), `official-installer` (%LOCALAPPDATA%\Programs\OpenAI\Codex\bin), `winget` (WinGet's links and packages), `system` (/opt/homebrew/bin, /usr/local/bin, /usr/bin), `scoop`, `chocolatey`, `volta`, `bun`, `pnpm`, `yarn`, `nvm` (nvm-windows), `fnm`, `vscode-extension` (the OpenAI extension's bundled codex.exe), `registry` (App Paths or an Uninstall entry), `drive-scan` (the background scan of the local drives)
- `processLocator` (`electron/features/codex-runtime/locator.cjs`) — the locator of a process that has no host to inject one: a codex-app-server runtime built without a resolver (the dispatch helper builds its own, `helperLocator` in integration/dispatch.cjs)
- `codexExecutable` (`electron/features/codex-runtime/locator.cjs`) — `(env, platform) → file | null` through `processLocator`; the codex-app-server runtime's default resolver
- `scanDrives` (`electron/features/codex-runtime/drive-scan.cjs`) — `({ drives, names, probes, skipFolder, files, now, pause, limits }) → { hits, visited, stopped }`: the folders, breadth first, that hold a file of one of `names` or a file at one of `probes` below them; it knows no Codex layout (the locator gives them). Bounds as `LIMITS`: depth 4 below each drive root, at least 3 below a drive's Program Files* and tools-like top folders and below each Users\<user>\AppData\Local\Programs; never into Windows, $Recycle.Bin, System Volume Information, ProgramData\Microsoft, .git, node_modules (a package is probed by its path) or a link or junction, nor a folder `skipFolder` refuses (Agentrix's shim folder); at most 20 000 folders listed, 20 s on `now` and 5 hits, yielding (`pause`) before each folder
- `fixedDrives` (`electron/features/codex-runtime/drive-scan.cjs`) — `(env) → roots`: the local fixed drives (no network, removable or optical drive) read through the environment's own PowerShell; none without SystemRoot, the system drive when the read fails
- `packageBinaries` (`electron/features/codex-runtime/locator.cjs`) — the npm layout table above, `(packageDir, arch, path) → [file, layout][]`, which the terminal probes' `resolveCli` (scripts/codex-cli-resolution.cjs) shares
