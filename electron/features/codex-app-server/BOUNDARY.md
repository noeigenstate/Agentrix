# Boundary: Codex app-server runtime

Owns an independent app-server runtime over local stdio or an injected SSH byte stream for a native Codex session; normalizes its events and keeps request tickets and input receipts within that session.

## Owns
- `electron/features/codex-app-server/**`

## Interface
- `createCodexRuntime` (`electron/features/codex-app-server/index.cjs`) — injected local and remote process launchers, executable resolver and clock; provides create(spec, emit), limits(scope), and a read-only history(spec, { signal }) lookup through thread/list and thread/read, returning { id, title, at } with a nullable millisecond timestamp. History admits cli and vscode sources, including the runtime's own app-server threads. A runtime provides start, resume, send, interrupt, answer, cancel, snapshot, close and read-only account reads. GUI planners retain their host-provided project bootstrap for authenticated helpers; dispatch workers strip it.
- `commands` (`electron/features/codex-app-server/index.cjs`) — native built-ins plus cached enabled skills from `skills/list` for its own cwd; selected slash skills become structured skill input using the host-held path, never a renderer-supplied path. `models` reads the provider catalog; `runOptions` validates model, effort and Fast choices, keeps them as host-only metadata scoped by CLI home/thread or authenticated SSH scope/thread, and applies them on the next turn; a choice made while the session starts waits for its thread. `shell` uses thread/shellCommand
- `createRpc` (`electron/features/codex-app-server/rpc.cjs`) — bounded stdio transport, also used by the separately admitted owner reset-credit client; it keeps only a bounded stderr tail, never published as an event, and `diagnostics()` hands it with the exit to a failed start, whose `error.detail` (failure.cjs) is one redacted line of stage, code or protocol error, exit and last stderr lines

## Invariants
- An optional missing skills RPC leaves native built-ins usable and lists no terminal-only commands; skill changes invalidate the bounded catalog. Native built-ins are protocol controls, unsupported known built-ins never become model text, and custom names/skills remain input. Only catalog-admitted choices persist through resume/new conversation, without changing user CLI configuration; an uncertain command never retries. Review child turn starts use the provider root identity and compaction/shell finish only on provider events — test: `tests/native-commands-codex.test.cjs` › "an unavailable optional skills RPC returns no terminal commands and leaves the connection usable". Automatic compaction and its pre-turn/in-turn/post-turn limits stay in the shared CLI core; no host threshold or supplementary compact RPC is added. A compaction's retrying provider errors keep its working state; final failure reports a classified reason without raw API JSON — test: `tests/native-autocompact-codex.test.cjs` (real 0.166, local service only); `tests/native-autocompact-events.test.cjs`.
- Input written before a disconnect receives unknown and is never automatically submitted again — duplicate execution changes the workspace twice — test: `tests/codex-app-server-runtime.test.cjs` › "steer written before process loss becomes unknown, and duplicates never restart it".
- Busy messages steer the active turn with an expected turn identity; a message ID cannot name different input. After a confirmed owner reset, only an explicitly empty failed usage-limit turn with no execution or consumption evidence can retry its original input, once; partial, consumed and unknown turns never replay — test: `tests/codex-app-server-runtime.test.cjs` › "busy input steers the same turn, duplicate IDs are idempotent and conflicts fail"; test: `tests/codex-auto-reset-runtime.test.cjs` › "reset-unread: confirmed reset replays only a proved empty unconsumed turn, at most once".
- Request tickets wait for an explicit answer, are consumed once and expire with the session — closing or stale UI never approves a command — test: `tests/codex-app-server-runtime.test.cjs` › "request tickets wait, are consumed once, and closing cancels them without auto allow". `cancel(requestId)` refuses one ticket in the protocol's form for its kind (an approval's cancel, an empty permission grant, a form's cancel, an empty answer map for a question, which has no decline) — test: `tests/codex-app-server-requests.test.cjs` › "cancel sends the protocol refusal of each kind once and never an approval".
- Usage and limits are snapshots; absent values remain null and sparse updates retain prior fields — token activity and a reset date cannot prove remaining subscription allowance — test: `tests/codex-app-server-runtime.test.cjs` › "sparse limits retain missing fields, never infer recovery, and reject unsafe integers".
- Completed items replace their deltas; raw reasoning is never displayed. Host local-command items are retained in snapshots too. /status and /usage are read-only: their facts (session, account, tokens, both quota windows, per-source read failures) travel only in the send receipt's `local` field, and they publish no item, no input receipt event and no turn — account and quota read failures stay visible as codes, never the server's words — reconstruction must not duplicate the response or disclose internal reasoning — test: `tests/codex-app-server-runtime.test.cjs` › "final items replace deltas, duplicate finals and raw reasoning are ignored"; test: `tests/native-codex-status.test.cjs` › "Codex /status and /usage answer in the receipt only: no item, receipt event, turn or snapshot entry". They take no place in the send queue. A dispatched worker's text is never a command: no leading "/" or "!" is run or refused for it, and none attaches a skill — test: `tests/native-codex-status.test.cjs` › "a /status still reading keeps no message waiting behind it"; test: `tests/native-codex-status.test.cjs` › "a dispatched worker’s text is never a command: a leading / or ! goes to the model as written". History replayed on resume is never running work. An item it left unfinished is kept and published as interrupted when its turn was recorded interrupted, otherwise as unknown; an item this process saw live is never replaced by its replayed copy; `activity()` counts only sub-agents, commands and tools started in this process — a stale count refuses a new conversation and holds a switch forever — test: `tests/codex-replay-activity.test.cjs` › "a resumed thread’s unfinished history is not running work: a new conversation starts, and work started here still blocks it".
- Local and SSH planners send developer instructions on start and resume. Local launch cwd expands only Windows 8.3 components; other aliases retain CLI trust/config scope, and both slash forms in developer instructions follow a changed cwd. Identity comparisons still recognize aliases, including CODEX_HOME occupancy. Automatic continuation verifies the persisted final turn through app-server and consumes its crash marker before sending once. SSH history uses its own abortable read-only remote channel, reaps a late connection after cancellation and never consumes a startup delivery. Windows writable workers may retry once with request-scoped unelevated sandboxing, without changing GUI policy or user configuration. A resumed thread is exclusively occupied until close inside the host — two runtimes must not write the same thread — test: `tests/codex-app-server-runtime.test.cjs` › "resumed threads have exclusive occupancy and release on close"; test: `tests/native-parity-review.test.cjs` › "B1 local Codex start and resume transmit developer instructions"; test: `tests/codex-only-real-cli.test.cjs` › "real app-server starts and resumes the same thread despite legacy terminal settings; missing CLI never falls back".
- Resume requests exclude full history; all input frames are bounded to 64 MiB and an oversized frame is drained without disconnecting the live session; only its matching pending response fails, and image pixels are discarded before publication. Frames use native JSON.parse with a separate iterative image-metadata pass for escaped or image candidates; no whole-frame regular expression or reviver runs; shrinking a history page produces no dropped-item notice, while skipping a single oversized turn does — long history must not force a transport fallback — test: `tests/codex-app-server-long-thread.test.cjs` › "oversized history is drained without disconnect, replay or losing another response". When an oversized frame cannot identify its nested item, unfinished tools settle as unknown even when the turn fails elsewhere, never failed or interrupted. Explicit turn interruption retains interrupted items, and a new turn clears the frame-loss observation — test: `tests/native-ui-backend.test.cjs` › "D6 oversized command results settle neutrally without changing true interruption". Local process exit releases inherited pipe ends even when a CLI metadata child holds them; SSH still requires its remote close receipt ? test: `tests/native-ui-backend.test.cjs` ? "an exited local app-server releases inherited pipes without reporting a process stop timeout".
