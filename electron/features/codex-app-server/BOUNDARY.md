# Boundary: Codex app-server runtime

Owns an independent app-server runtime over local stdio or an injected SSH byte stream for a native Codex session; normalizes its events and keeps request tickets and input receipts within that session.

## Owns
- `electron/features/codex-app-server/**`

## Interface
- `createCodexRuntime` (`electron/features/codex-app-server/index.cjs`) — injected local and remote process launchers, executable resolver, clock and deadline timers, and a generated picture's renderImage and settleImage (features/generated-images); provides create(spec, emit), limits(scope), and a read-only history(spec, { signal }) lookup through thread/list and thread/read, returning { id, title, at } with a nullable millisecond timestamp. History admits cli and vscode sources, including the runtime's own app-server threads. A runtime provides start, resume, send, interrupt, answer, cancel, snapshot, close and read-only account reads. GUI planners retain their host-provided project bootstrap for authenticated helpers; dispatch workers strip it. The entrypoint also exports createRpc and stopProcess for main to inject into model-only probes without a provider dependency in Skills.
- `commands` (`electron/features/codex-app-server/index.cjs`) — native built-ins plus enabled skills cached for their cwd; a selected skill uses its host-held path. `models` reads a fresh provider catalog, retaining advertised effort, default effort, fast/priority and default-model metadata. `runOptions` reads the launch route and changes only permissions. The host's frozen seat determines model, effort and fast on start, resume and subsequent turns. The owner also reads or changes `permissions` (full, config, ask; unknown reads as full), for this thread only. A target probe is retained for the same CLI home, process and request while valid; a changed request or provider close invalidates it, and a late announcement is abandoned only after a probe timeout. Settings updates always name the user as approver. A complete matching settings notice after the actual write, within its confirmation deadline, confirms the change; missing approvalsReviewer stays uncertain, and managed-policy refusals say why. A running turn keeps its current permissions. Local Windows can take ask only when the thread started writable. Permissions never change CLI configuration or persisted choices. `shell` uses thread/shellCommand.
- `createRpc` (`electron/features/codex-app-server/rpc.cjs`) — bounded stdio transport, also used by the admitted owner reset-credit client; request(method, params, deadline, { onWritten, timeoutFromWrite }) reports an actual write, including after backpressure, never an expired queued request; timeoutFromWrite keeps queue admission bounded and gives a written settings update its full response interval. A failed process's diagnostics wait for child close before returning its bounded stderr tail and exit; a live server's protocol rejection returns immediately. close() fails pending requests only; ending the input belongs to the process stop. Startup error.detail remains one redacted line from agents/start-failure.cjs; stderr is never published as an event.

## Invariants
- An optional missing skills RPC leaves native built-ins usable and lists no terminal-only commands; skill changes invalidate the bounded catalog. Native built-ins are protocol controls, unsupported known built-ins never become model text, and custom names/skills remain input. Model, effort and fast commands are refused in owner sessions. Resume sends the current launch seat and leaves CLI configuration untouched. An uncertain command never retries. Review child turn starts use the provider root identity and compaction/shell finish only on provider events — test: `tests/native-commands-codex.test.cjs` › "an unavailable optional skills RPC returns no terminal commands and leaves the connection usable". Automatic compaction and its pre-turn/in-turn/post-turn limits stay in the shared CLI core; no host threshold or supplementary compact RPC is added. A compaction's retrying provider errors keep its working state; final failure reports a classified reason without raw API JSON — test: `tests/native-autocompact-codex.test.cjs` (real 0.166, local service only); `tests/native-autocompact-events.test.cjs`. test: `tests/codex-slash.test.cjs` › "Codex resume sends the current seat even with saved beta thread settings"
- Input written before a disconnect receives unknown and is never automatically submitted again — duplicate execution changes the workspace twice — test: `tests/codex-app-server-runtime.test.cjs` › "steer written before process loss becomes unknown, and duplicates never restart it".
- Busy messages steer the active turn with an expected turn identity; a message ID cannot name different input. After a confirmed owner reset, only an explicitly empty failed usage-limit turn with no execution or consumption evidence can retry its original input, once; partial, consumed and unknown turns never replay — test: `tests/codex-app-server-runtime.test.cjs` › "busy input steers the same turn, duplicate IDs are idempotent and conflicts fail"; test: `tests/codex-auto-reset-runtime.test.cjs` › "reset-unread: confirmed reset replays only a proved empty unconsumed turn, at most once".
- Request tickets wait for an explicit answer, are consumed once and expire with the session — closing or stale UI never approves a command — test: `tests/codex-app-server-runtime.test.cjs` › "request tickets wait, are consumed once, and closing cancels them without auto allow". `cancel(requestId)` refuses one ticket in the protocol's form for its kind (an approval's cancel, an empty permission grant, a form's cancel, an empty answer map for a question, which has no decline) — test: `tests/codex-app-server-requests.test.cjs` › "cancel sends the protocol refusal of each kind once and never an approval".
- Usage and limits are snapshots; absent values remain null and sparse updates retain prior fields — token activity and a reset date cannot prove remaining subscription allowance — test: `tests/codex-app-server-runtime.test.cjs` › "sparse limits retain missing fields, never infer recovery, and reject unsafe integers".
- Completed items replace their deltas; raw reasoning is never displayed. Host local-command items are retained in snapshots too. /status and /usage are read-only: their facts (session, account, tokens, both quota windows, per-source read failures) travel only in the send receipt's `local` field, and they publish no item, no input receipt event and no turn — account and quota read failures stay visible as codes, never the server's words — reconstruction must not duplicate the response or disclose internal reasoning — test: `tests/codex-app-server-runtime.test.cjs` › "final items replace deltas, duplicate finals and raw reasoning are ignored"; test: `tests/native-codex-status.test.cjs` › "Codex /status and /usage answer in the receipt only: no item, receipt event, turn or snapshot entry". They take no place in the send queue. A dispatched worker's text is never a command: no leading "/" or "!" is run or refused for it, and none attaches a skill — test: `tests/native-codex-status.test.cjs` › "a /status still reading keeps no message waiting behind it"; test: `tests/native-codex-status.test.cjs` › "a dispatched worker’s text is never a command: a leading / or ! goes to the model as written". History replayed on resume is never running work. An item it left unfinished is kept and published as interrupted when its turn was recorded interrupted, otherwise as unknown; an item this process saw live is never replaced by its replayed copy; `activity()` counts only sub-agents, commands and tools started in this process — a stale count refuses a new conversation and holds a switch forever — test: `tests/codex-replay-activity.test.cjs` › "a resumed thread’s unfinished history is not running work: a new conversation starts, and work started here still blocks it".
- Local and SSH planners send developer instructions on start and resume. Local launch cwd expands only Windows 8.3 components; other aliases retain CLI trust/config scope, and both slash forms in developer instructions follow a changed cwd. Identity comparisons still recognize aliases, including CODEX_HOME occupancy. Automatic continuation verifies the persisted final turn through app-server and consumes its crash marker before sending once. SSH history uses its own abortable read-only remote channel, reaps a late connection after cancellation and never consumes a startup delivery. Windows writable requests (a worker, or the owner's "ask") may retry once with request-scoped unelevated sandboxing, without changing user configuration. The owner's session sends its permissions choice (full: never + danger-full-access; config: neither; ask: on-request + workspace-write) on start and resume; dispatched and read-only sessions keep their own sandbox whatever it says, approvals always go to the user, and a sandbox Codex reports other than requested stops the start, or refuses /permissions, with its reason — test: `tests/codex-permissions.test.cjs` › "dispatched and read-only sessions keep their own sandbox and approvals whatever the permissions say"; test: `tests/codex-permissions.test.cjs` › "a sandbox Codex did not apply stops the start and says why: full, ask over SSH, and ask on Windows after one unelevated retry". Every app-server stand-in under tests/fixtures answers the sandbox and approvals it is asked for, so this check never stops a smoke on one platform only — test: `tests/fake-cli-contract.test.cjs` › "every Claude and Codex stand-in found under tests/ and scripts/ is registered in tests/fixtures/stand-ins.json and echoes the settings, hooks, sandbox and approvals it is given". A resumed thread is exclusively occupied until close inside the host — two runtimes must not write the same thread — test: `tests/codex-app-server-runtime.test.cjs` › "resumed threads have exclusive occupancy and release on close"; test: `tests/native-parity-review.test.cjs` › "B1 local Codex start and resume transmit developer instructions"; test: `tests/codex-only-real-cli.test.cjs` › "real app-server starts and resumes the same thread despite legacy terminal settings; missing CLI never falls back". Permissions probe reuse, late cleanup and write-based confirmation stay event-driven; no old snapshot supplies a missing reviewer. test: `tests/codex-permissions.test.cjs` › "/permissions reuses a valid probe per CLI home"; test: `tests/codex-permissions.test.cjs` › "/permissions releases a late probe only after timeout"; test: `tests/codex-permissions.test.cjs` › "/permissions waits past stale notices before the reply"; test: `tests/codex-permissions.test.cjs` › "/permissions starts confirmation timing at the request write"; test: `tests/codex-permissions.test.cjs` › "/permissions missing approvalsReviewer reports may have been applied"; test: `tests/codex-permissions.test.cjs` › "/permissions managed policy forbidding workspace-write reports a policy refusal"; test: `tests/codex-permissions-real-cli.test.cjs` › "real app-server: each permissions choice starts as asked, and /permissions changes the running thread from its next turn"; test: `tests/codex-permissions.test.cjs` › "Codex 0.166 refuses /permissions through its unsupported-method path without changing the session"; test: `tests/codex-permissions.test.cjs` › "real permissions CI uses private Codex 0.167 while the minimum-version jobs keep 0.166".
- Resume requests exclude full history; all input frames are bounded to 64 MiB and an oversized frame is drained without disconnecting the live session; only its matching pending response fails, and image pixels are discarded before publication. Frames use native JSON.parse with a separate iterative image-metadata pass for escaped or image candidates; no whole-frame regular expression or reviver runs; shrinking a history page produces no dropped-item notice, while skipping a single oversized turn does — long history must not force a transport fallback — test: `tests/codex-app-server-long-thread.test.cjs` › "oversized history is drained without disconnect, replay or losing another response". When an oversized frame cannot identify its nested item, unfinished tools settle as unknown even when the turn fails elsewhere, never failed or interrupted. Explicit turn interruption retains interrupted items, and a new turn clears the frame-loss observation — test: `tests/native-ui-backend.test.cjs` › "D6 oversized command results settle neutrally without changing true interruption". Closing a local session stops the app-server's whole process tree before its input ends (Windows: taskkill /t while the server is still alive, since Codex leaves on end of input and its children outlive it; elsewhere its process group) and returns once the server has exited and the tree stop has finished, within 3 s — a leftover shell or helper would keep running and hold the project folder — test: `tests/codex-app-server-runtime.test.cjs` › "closing a local session stops every process its app-server started, and the folder they ran in can be removed"; test: `tests/native-ui-backend.test.cjs` › "a Windows stop waits for taskkill to finish with the tree, even after the app-server has exited and closed". So closing or switching a local session ends every process that session started, including a long-running command the owner started through it. Codex is force-stopped at close on every platform: nothing Codex would write at end of input is relied on, and a thread closed right after a turn resumes with that turn's items and saved token count — test: `tests/codex-permissions-real-cli.test.cjs` › "real app-server: a thread closed right after a turn resumes with that turn and its token count". Local process exit releases inherited pipe ends even when a CLI metadata child holds them; SSH still requires its remote close receipt — test: `tests/native-ui-backend.test.cjs` › "an exited local app-server releases inherited pipes without reporting a process stop timeout". Startup failure details follow child close under all six stderr/stdout-end/exit orders, or the end of the host's bounded stop when close never arrives — test: `tests/codex-app-server-runtime.test.cjs` › "startup diagnostics end when the bounded stop settles, even when the exited child never reports close"; test: `tests/codex-app-server-runtime.test.cjs` › "a failed start carries its stage, exit code and redacted stderr tail, and a protocol error its code and message"; test: `tests/codex-app-server-runtime.test.cjs` › "RPC write receipts follow the actual write, including backpressure, and never fire for an expired queued request"; test: `tests/codex-app-server-runtime.test.cjs` › "a permissions RPC gets its full response deadline after a queued write"; test: `tests/codex-app-server-runtime.test.cjs` › "a failed start reaps an exited child whose inherited pipes keep close open".
