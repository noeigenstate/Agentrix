# Boundary: Lab oss source

The Virtual Lab's oss task source: curated SWE-bench Verified Python tasks from small repositories, cloned at a pinned commit and graded natively with pytest. It meets the source contract (`electron/features/lab/sources/contract.cjs`) and reaches the machine only through the tools and session in its context.

Trust limit: grading imports model-edited subject source into the same Python interpreter as pytest and the evidence
observer. The invocation nonce is not an in-process authenticity boundary: source can inspect `__main__` or
`sys.orig_argv`, replace pytest/reporting code, forge a frame or exit directly. Pytest-subject tasks necessarily permit
changes to parts of the runner itself. Environment/control verification, restored tests, isolated Python, disabled
plugin autoload and strict evidence checks mitigate filesystem tampering; they do not completely prevent in-process
forgery. A pristine independent outer runner is not implemented.

## Invariants
- The provider meets the source contract: describe never throws, ids match TASK_ID, sampling is deterministic, a forged id is rejected, and no task, description or workspace carries an answer or a fixture secret — every source must be safe to run and show through one engine and one page — test: `tests/lab-oss.test.cjs` › "the oss provider meets the source contract"
- The shipped manifest holds twelve pinned tasks as metadata only (no problem statement, no patch); describe and sample never touch the network, and the engine's second `canonical` after `fetch` is what fills in the problem statement — a cold cache can be sampled offline and nothing from the dataset ships in the app — test: `tests/lab-oss.test.cjs` › "the shipped manifest contains twelve pinned Python tasks, metadata only, with attribution"; test: `tests/lab-oss.test.cjs` › "describe and sample are manifest-only even with broken machine tools"; test: `tests/lab-oss.test.cjs` › "fetch verifies data and Git identity; the second canonical hydrates only the problem statement"
- A task is resolved (score 1, otherwise 0) only when every pinned fail-to-pass and pass-to-pass case is reported passing, with hidden tests and pytest configuration restored first; missing, duplicate, renamed, skipped, errored or malformed evidence is never a pass — the lab must not invent success — test: `tests/lab-oss.test.cjs` › "grade restores hidden tests and reports resolved only when both groups pass"; test: `tests/lab-oss.test.cjs` › "missing, duplicate, renamed, skipped, malformed and errored evidence is never a pass"
- Downloads are checked against the manifest's SHA-256 and Git identity before use, and a changed row or grading patch is fatal; dependencies are installed only in the preparation call that asks for the network, once per dependency hash at a time, from checksum-verified wheels cached by Python runtime and platform — a tampered dataset or package never reaches a model — test: `tests/lab-oss.test.cjs` › "a corrupt download never publishes a row or reaches Git"; test: `tests/lab-oss.test.cjs` › "a changed private row or grading patch is fatal to the guard"; test: `tests/lab-oss.test.cjs` › "concurrent preparations serialize installation for the same dependency hash"; test: `tests/lab-oss.test.cjs` › "wheel checksum corruption is refused before another installation"
- Preparation seals every Python environment file, directory and internal link in artifacts outside the model write roots; before each comparison grading deletes only unsealed derived bytecode/cache files and their empty cache directories, then checks the seal before Python starts and after it exits; new source, pth and binary files and any changed or removed sealed file, including sealed pyc, remain logged run errors — ordinary model-side pytest plugin rewriting stays gradable without trusting its generated bytecode — test: `tests/lab-oss.test.cjs` › "a model-added pth file is a logged run error before Python can execute it"; test: `tests/lab-oss.test.cjs` › "the environment seal checks changed, removed and newly added files and directories"; test: `tests/lab-oss.test.cjs` › "unsealed environment caches are removed before verification while sealed bytecode stays immutable"
- Repository startup hooks, pytest configuration sections and reference-discovered non-subject plugins are preparation-pinned; test trees are restored to the pinned base plus the hidden test patch and added regression files are removed or ignored; all subject source remains editable, including pytest's own modules and new helpers outside the reference diff; a reference edit to a true control accepts its validated control bytes; inherited pytest options are cleared, conftest discovery is confined to the repository, parent configuration is bypassed and model bytecode is discarded or rejected — these checks cover the filesystem control plane within the stated in-process trust limit — test: `tests/lab-oss.test.cjs` › "repository startup files and pytest options cannot change the grader"; test: `tests/lab-oss.test.cjs` › "a pinned reference change to a grading control is accepted without allowing a different injected hook"; test: `tests/lab-oss.test.cjs` › "alternative pytest source fixes and new regression tests are not restricted to reference files"; test: `tests/lab-oss.test.cjs` › "non-pytest configuration edits are allowed while pytest sections remain pinned"
- Grading receives invocation-tagged setup, call and teardown events over process stdout, validates their names, phases and exit code, and main writes the JUnit artifact; pre-placed or raced workspace JUnit reports are logged run errors and are never read as evidence — workspace report files cannot supply the result, while imported subject code retains the in-process forgery risk described above — test: `tests/lab-oss.test.cjs` › "pre-placed and raced JUnit reports are errors and never result evidence"; test: `tests/lab-oss.test.cjs` › "real pytest proves reference and source fixes, and rejects pth, conftest and report tampering"
