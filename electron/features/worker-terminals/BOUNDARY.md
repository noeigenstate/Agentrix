# Boundary: Worker terminals

Under a local terminal lead, a dispatched Claude worker runs as a hidden interactive `claude` in a PTY of its own, billed like the lead's terminal: main starts it, routes its hooks, reads its transcript into the dispatch stream, lets the owner answer its confirmations from the split, and kills it when the run ends.

## Owns
- `electron/features/worker-terminals/**`

## Interface
- `createWorkerTerminals` (`electron/features/worker-terminals/worker-terminals.cjs`) — `(deps) → { create, keyOf, hook, event, register, closeAll }`: `create(run, spec, stream)` is the runtime native-session/worker.cjs drives (`start`, `resume`, `send`, `close`) and publishes native-shaped events on its stream (`path.changed` selected `terminal-worker`, `turn.started` on UserPromptSubmit, compacted `transcript.record`, the final `item.upsert` agent-message, `turn.completed` and `session.state` idle on Stop); `keyOf`/`hook` sit in front of main's hook ingest and `event` in front of its event pipe; `register({ handle, listen })` serves `worker-terminal:attach`, `:keys`, `:resize` and `:detach` (the split's data arrives as `worker-terminal:data`); `closeAll` at quit, a promise that never rejects
- `meterRecord` (`electron/features/worker-terminals/worker-terminals.cjs`) — what of a transcript record reaches the dispatch helper's meter

## May import
- `electron/shared/agentrix-shims.cjs` (withoutShims: the worker starts from the owner's environment)
- `electron/transcript-tail.cjs` (following the worker's transcript)
- `electron/claude-sessions.cjs` (findClaudeSession: the transcript found by session id under the worker's own Claude home)

## Invariants
- Only an authenticated `leadMode: 'terminal'` binding with `run.local` true, whose terminal still runs Claude in terminal mode, gets a worker terminal; SSH projects and Codex or native leads keep their path. The worker's env is the parent terminal's environment as it was when that terminal started (a variable the owner's shell profile sets later is not in it), minus Agentrix credentials, the reading note, the shell integration's wiring and CLAUDE_CODE_ENTRYPOINT, with the user's own ZDOTDIR back; no client identity, API key or `-p` is added, and no model, effort, permission or resume value can start with a dash. Its billing path is subscription and its token totals and cost stay unknown in this wave — test: `tests/terminal-workers.test.cjs` › "billing follows the lead's mode and no client identity is set"; test: `tests/terminal-workers.test.cjs` › "a value that would become a CLI option is refused before launch"
- A worker terminal is never a project terminal: it is not in `sessions` or the store, never restored, never listed in the project's Claude history, never counted in the all-complete check and never arms or rearms a completion notification; its hooks and command-hook events are taken before any project terminal's, by its own key, and command hooks count in the order they were sent — test: `tests/terminal-workers.test.cjs` › "a worker's hooks never reach a project terminal or its completion"; test: `tests/terminal-workers.test.cjs` › "command hooks count in the order they were sent"
- Hooks add no model context: the worker's --settings are exactly terminalHooks(), there is no note file, and every hook is answered `{}` by the hook server; the settings and the start-up hook copy sit outside the worker's only `--add-dir` (its `brief/` folder) — test: `tests/terminal-workers.test.cjs` › "a worker's hooks never reach a project terminal or its completion"
- The brief and every owner message go in as files in the worker's `brief/` folder, named by one fixed typed sentence; no part of their text is typed. A message is written once, only while the CLI waits for a prompt (after Stop, or after an Esc or a rejected tool, when the row waits for the owner), confirmed by UserPromptSubmit, never resent — test: `tests/terminal-workers.test.cjs` › "an intervention is written once when idle and never resent"; test: `tests/terminal-workers.test.cjs` › "an interrupted turn waits for the owner and takes the next message"
- `--out` is the turn's final reply from the transcript (a final stop reason, or text with no tool call), checked against the Stop hook's text; without that record within a bounded wait it is the hook's text, and with neither there is none. Transcript reads are one at a time; the helper's meter gets only compacted records (`transcript.record`, no full text, within its bound), each after the item that names its input channel, and never the renderer — test: `tests/terminal-workers.test.cjs` › "a terminal planner's worker shows its rate, waits for the owner and writes output on Stop"; test: `tests/terminal-workers.test.cjs` › "the final answer is the turn's final record, or the Stop hook's text when that record never arrives"; test: `tests/terminal-workers.test.cjs` › "transcript reads never overlap and an oversized record still reaches the meter"
- Only the owner answers the worker's confirmations: keys from its open split reach that worker's PTY only while it awaits the owner (a permission or elicitation hook, an interruption, or a start-up dialog drawn 15 s without a prompt), which stays until the next progress hook; nothing is answered automatically. A read-only or roundtable worker runs in plan mode, which the owner can lift in the split — test: `tests/terminal-workers.test.cjs` › "keys reach the worker only while it awaits the owner"; test: `tests/terminal-workers.test.cjs` › "the split's bridge runs through main's IPC adapter and the preload"
- The worker delegates only through the dispatcher: it runs at shim depth 1 with its run identity and a proof from the parent's session key, and its CLAUDE_ENV_FILE is its own private copy, never the parent's — test: `tests/terminal-workers.test.cjs` › "billing follows the lead's mode and no client identity is set"
- Stop, disconnect and quit kill the PTY tree and remove the private folder once its exit is seen, retried a bounded number of times; closing never fails, so the run always ends, interrupted or failed — test: `tests/terminal-workers.test.cjs` › "keys reach the worker only while it awaits the owner"; test: `tests/terminal-workers.test.cjs` › "closing never fails while Windows holds the folder"

## Not ours
- Choosing the worker's path and the SDK runtime — Native session router (worker.cjs) and claude-sdk
- The dispatch helper, its run binding and the billing it reports — Dispatch (integration/dispatch.cjs)
- A project terminal's hooks, state machine and completion — Terminal events
- The split that shows the worker's terminal — Sub-agent view (src/features/agents)
