# Boundary: Worker terminals

Under a local terminal lead, a dispatched Claude worker runs as a hidden interactive `claude` in a PTY of its own, billed like the lead's terminal: main starts it, routes its hooks, reads its transcript into the dispatch stream, lets the owner answer its confirmations from the split, and kills it when the run ends.
The worker stream reports active menu ids, kinds, titles and numbered choices. The main window parses the hidden PTY's output
with the same xterm buffer and menu parser as the visible terminals. Main accepts only the latest output sequence for that PTY.
The worker's synchronous permission hook has a 30 s budget on either hook channel. A permission notification and
current permission frame surface the owner wait even when the decision hook could not report it. Claude can still
accept a late hook decision after that notification, so automatic deny keys wait out the hook budget. The wait stays
visible until the CLI advances or clears its menu. Tests cover this with a fake clock and a captured permission screen.

Workers can run Bash commands and tests, with PowerShell also available on Windows. Both shells deny explicit Git
commit, push and reset --hard. The role decides which tests the task needs. Read-only workers use dontAsk and leave
project files untouched. Writable workers use acceptEdits and follow their assigned file scope.

## Owns

## Interface
- `createWorkerTerminals` (`electron/features/worker-terminals/worker-terminals.cjs`) — `(deps) → { create, keyOf, hook, event, register, closeAll }`: `create(run, spec, stream)` is the runtime native-session/worker.cjs drives (`start`, `resume`, `send`, `close`) and publishes native-shaped events on its stream (`path.changed` selected `terminal-worker`, `turn.started` on UserPromptSubmit, compacted `transcript.record`, the final `item.upsert` agent-message, `turn.completed` and `session.state` idle on Stop); `keyOf`/`hook` sit in front of main's hook ingest and `event` in front of its event pipe; `register({ handle, listen })` serves `worker-terminal:attach`, `:keys`, `:resize` and `:detach` (the split's data arrives as `worker-terminal:data`); `closeAll` at quit, a promise that never rejects
- `meterRecord` (`electron/features/worker-terminals/worker-terminals.cjs`) — what of a transcript record reaches the dispatch helper's meter

## Invariants
- Only an authenticated `leadMode: 'terminal'` binding with `run.local` true, whose terminal still runs Claude in terminal mode, gets a worker terminal; SSH projects and Codex or native leads keep their path. The worker's env is the parent terminal's environment as it was when that terminal started (a variable the owner's shell profile sets later is not in it), minus Agentrix credentials, the reading note, the shell integration's wiring and CLAUDE_CODE_ENTRYPOINT, with the user's own ZDOTDIR back and background policy replaced by the current Settings choice; no client identity, API key or `-p` is added, and no model, effort, permission or resume value can start with a dash. If the locator has no CLI, an existing absolute AGENTRIX_CLAUDE_EXECUTABLE from that parent is tried. A launch failure before input selects the helper's subscription CLI fallback; after input it fails visibly. CMD launches disable delayed expansion so exclamation marks stay literal. Its billing path is subscription and its token totals and cost stay unknown in this wave — test: `tests/terminal-workers.test.cjs` › "billing follows the lead's mode and no client identity is set"; test: `tests/terminal-workers.test.cjs` › "a value that would become a CLI option is refused before launch"; test: `tests/terminal-workers.test.cjs` › "each terminal launch failure before input selects the subscription CLI fallback"; test: `tests/terminal-workers.test.cjs` › "the parent terminal executable is tried only when it is an existing absolute file"; test: `tests/terminal-workers.test.cjs` › "a terminal launch failure after its initial input fails visibly without CLI fallback"; test: `tests/terminal-workers.test.cjs` › "cmd worker launch disables delayed expansion for exclamation marks in paths"; test: `tests/nobg-coverage.test.cjs` › "terminal worker environments override the saved parent choice"
- A worker terminal is never a project terminal: it is not in `sessions` or the store, never restored, never listed in the project's Claude history, never counted in the all-complete check and never arms or rearms a completion notification; its hooks and command-hook events are taken before any project terminal's, by its own key, and command hooks count in the order they were sent — test: `tests/terminal-workers.test.cjs` › "a worker's hooks never reach a project terminal or its completion"; test: `tests/terminal-workers.test.cjs` › "command hooks count in the order they were sent"
- Worker status hooks remain silent. A synchronous worker-only PermissionRequest command hook denies ordinary permission requests with a continuation message and reports a redacted refusal. Question and plan requests still reach the menu handling. The settings retain fastMode:true when the seat requests fast, there is no note file, and the settings and the start-up hook copy sit outside the worker's only `--add-dir` (its `brief/` folder) — test: `tests/terminal-workers.test.cjs` › "a worker's hooks never reach a project terminal or its completion"
- A short initial brief goes directly to the executable as one argument. Oversized or shell-shim launches use a reference to the private brief file. Later owner messages use files in the worker?s `brief/` folder, named by one fixed typed sentence. A message is written once, only while the CLI waits for a prompt (after Stop, or after an Esc or a rejected tool, when the row waits for the owner), confirmed by UserPromptSubmit, never resent. Split typing holds queued messages until the owner clears the draft with Ctrl+C or Ctrl+U, or submits it and that turn ends; pauses never release a draft, and the owner's submission does not consume the queued message. Owner keys and new questions cancel a pending automatic Enter — test: `tests/terminal-workers.test.cjs` › "an intervention is written once when idle and never resent"; test: `tests/terminal-workers.test.cjs` › "an interrupted turn waits for the owner and takes the next message"; test: `tests/terminal-workers.test.cjs` › "a queued intervention waits for the owner draft to be cleared or its submitted turn to finish"; test: `tests/terminal-workers.test.cjs` › "an unconfirmed queued sentence never blocks owner keys or sends Enter into a new dialog"
- `--out` is the turn's final reply from the transcript (a final stop reason, or text with no tool call), checked against the Stop hook's text; without that record within a bounded wait it is the hook's text, and with neither there is none. Transcript reads are one at a time; the helper's meter gets only compacted records (`transcript.record`, no full text, within its bound), each after the item that names its input channel, and never the renderer — test: `tests/terminal-workers.test.cjs` › "a terminal planner's worker shows its rate, waits for the owner and writes output on Stop"; test: `tests/terminal-workers.test.cjs` › "the final answer is the turn's final record, or the Stop hook's text when that record never arrives"; test: `tests/terminal-workers.test.cjs` › "transcript reads never overlap and an oversized record still reaches the meter"
- The owner or lead can answer a recognised question or plan menu. The lead uses `answer_role` and the current wait id. Recognised permission menus with an explicit deny option are denied automatically. Both paths use the split's PTY writer and send only the navigation and selection keys. The first non-empty owner key accepted from an attached split reserves that menu for the owner, including when the key arrives after the wait hook but before the menu frame. The reservation survives redraws and detaching the split, and ends when the host clears the wait. A frame without a menu forgets the old wait id. A still-current question or plan can offer one new answer after the clock-driven retry interval. Terminal protocol replies reach the PTY without reserving a menu. No other source writes menu keys. Owner keys from the open split reach that worker's PTY whenever it awaits the owner (a permission or elicitation hook, an interruption, or a start-up dialog drawn 15 s without a prompt), even while a typed message lacks UserPromptSubmit, with open questions keyed by tool-use or elicitation id. Only that question's result closes it; UserPromptSubmit, Stop, StopFailure, SessionEnd and transcript interruptions close all. The most recent 512 closed identities suppress late notices, oldest dropped first; unkeyed notices add no questions. Unrelated progress leaves keys available. Attachments are counted per view (legacy views share the one accepted owner sender), and only the last detach stops data and keys. Read-only launch uses dontAsk and exposes reading tools and Bash, plus PowerShell on Windows — test: `tests/terminal-workers.test.cjs` › "keys reach the worker only while it awaits the owner"; test: `tests/terminal-workers.test.cjs` › "a hidden terminal owner prompt reaches the real detached receipt and wakes wait_roles"; test: `tests/terminal-workers.test.cjs` › "the split's bridge runs through main's IPC adapter and the preload"; test: `tests/terminal-workers.test.cjs` › "parallel questions close only for their own result and late notices cannot reopen them"; test: `tests/terminal-workers.test.cjs` › "two attached splits keep data and keys until the last view detaches"; test: `tests/terminal-workers.test.cjs` › "an interruption closes every open ask without an answer hook and releases the queued message"; test: `tests/terminal-workers.test.cjs` › "closed questions retain only the most recent 512 identities"; test: `tests/terminal-workers.test.cjs` › "an unconfirmed queued sentence never blocks owner keys or sends Enter into a new dialog"
- The worker delegates only through the dispatcher: it runs at shim depth 1 with its run identity and a proof from the parent's session key, and its CLAUDE_ENV_FILE is its own private copy, never the parent's — test: `tests/terminal-workers.test.cjs` › "billing follows the lead's mode and no client identity is set"
- Stop, disconnect and quit kill the PTY tree and remove the private folder once its exit is seen, retried a bounded number of times; closing never fails, so the run always ends, interrupted or failed. Windows never uses POSIX process-group signals, including while the PTY's pid is zero; POSIX signals only positive integer pids. ConPTY cleanup kills the agent directly only with `_isReady === false`, registers a PTY error listener at launch, destroys the output socket before terminating its worker and bounds termination by the exit deadline. Worker callbacks cannot arm after close or exit; awaited cleanup timers remain tracked. Main includes closeAll in its quit drains and waits for the bounded tree shutdown before quitting again — test: `tests/terminal-workers.test.cjs` › "keys reach the worker only while it awaits the owner"; test: `tests/terminal-workers.test.cjs` › "closing never fails while Windows holds the folder"; test: `tests/terminal-workers.test.cjs` › "quit waits for worker terminal tree shutdown before asking Electron to quit again"; test: `tests/terminal-workers.test.cjs` › "win32 real tree shutdown never signals pid zero"; test: `tests/terminal-workers.test.cjs` › "linux real tree shutdown never signals pid zero"; test: `tests/terminal-workers.test.cjs` › "POSIX real tree shutdown signals only a positive integer process group"; test: `tests/terminal-workers.test.cjs` › "Windows quiet ConPTY teardown closes its sockets and output worker without another data event"; test: `tests/terminal-workers.test.cjs` › "a PTY exiting during listener registration cannot arm a startup notice"; test: `tests/terminal-workers.test.cjs` › "Windows conout worker termination cannot extend the exit deadline"
