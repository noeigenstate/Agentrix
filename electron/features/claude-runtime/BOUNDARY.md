# Boundary: Claude runtime

Where Claude Code is on this machine, for the terminal and the native path alike: one search order, one cache, and the
Windows PATH merge it searches. Main keeps one locator; the native path runs its `native` file (through
`claude-sdk/executable.cjs`), a local terminal is told its `terminal` file in `AGENTRIX_CLAUDE_EXECUTABLE`, and the
agents' state reads its last result.

Which program a terminal's `claude` runs, highest first: an alias for claude in the user's start-up files (bash, zsh),
then `AGENTRIX_CLAUDE_EXECUTABLE` while that file exists, then the wrapper's own PATH search. An SSH project's terminal
is never told one. The wrappers' own search is deliberately left narrower than the locator's this round (bootstrap.ps1:
the first claude on PATH, a shim mapped to its npm package's bin/claude.exe; bash and zsh: the first on PATH); it runs
only when no file was chosen. An alias that makes the terminal run another program than the native path is not seen by
the locator, an accepted gap.

The PATH merge has two implementations with one meaning: `integration/refresh-path.ps1` in a terminal's PowerShell and
`mergePath` here. Both keep the inherited PATH first and append every entry of the stored machine then user PATH,
each expanded against the environment (%NAME% of a defined variable, anything else as written), that is not already
there; an entry is kept as written (trimmed), and two entries are the same folder when they match without quotes, with
/ as \ and without trailing \ (a drive root keeps its own), letter case ignored; a scope that cannot be read adds nothing.

It also owns how the Claude path is decided (C-11): the resolver holds the facts a path is decided from, each with its
scope, fingerprint and expiry, and `decide()` turns them and the run mode into the path and its reason for every caller:
a new or running session, the connection test, the usage panel and, through the wrappers kept for it until R4, the
dispatcher's worker. The windows are still told the names and sentences they were told before (`wire`); the reasons
themselves are `claude.*` codes.

## Interface
- `createLocator` (`electron/features/claude-runtime/locator.cjs`) — `{ locate, refresh, peek }` over injected `probe`, `files`, `storedPath`, `now` and version-check `timers` (`setTimeout`, `clearTimeout`, `now`). `locate({ env, platform, arch, home })` and `refresh(…, { throttled })` give `{ terminal, native, reason, pathHash, effectivePath }`, where `terminal` (the first Claude Code found that printed a version) and `native` (the first that meets `REQUIRED`) are `{ file, path, fileShown, version, via, fingerprint: { file, size, mtimeMs, pathHash } }` or null, and are the same object when they are the same file; `file` is the real file, `path` where it was found (a link stays a link: a terminal is told this one), `fileShown` the file with home as `~`. `reason` is null, `cli_split_versions` (two different files), `too_old` (with `version`), the failed check's `timeout`, `failed` or `unreadable` (with `failure: { reason, found, error?, elapsedMs? }`), or `not_found` (with `pathFolders`, `searched` and `incomplete` for an npm package without its native program). Search order: the effective PATH (inherited, then the stored Windows PATH merged by `mergePath`), each folder as the wrapper takes it (Windows: claude.ps1, claude + each PATHEXT, bare claude; a shim that comes before claude.exe puts its npm package first, and a shim names a package only inside its own folder, never a UNC path; npm's placeholder bin/claude.exe gives way to the platform package's copy; a cli.js package reads as too old by its package.json and is not run), then ~/.local/bin, ~/.claude/local, WinGet's links (Windows) or the system folders (elsewhere); paths follow `platform`'s rules on any host. An explicit `refresh` (start-up, the connection test, an install) reads the stored Windows PATH and searches; a `throttled` one (window focus) does that at most once a minute and otherwise answers as a locate. A `locate` keeps the last answer under the same PATH: a found CLI while its `path` still leads to the same file at the same size and mtime, a failed check for ten seconds, nothing found until the next refresh. `--version` runs once per file, size and mtime; one that printed no version is trusted for ten seconds by a locate and a throttled refresh, and run again by an explicit one. Overlapping calls share one search, and refreshes asked for while one runs are done once after it. `peek()` is the last result, null before the first search
- `VIAS` (`electron/features/claude-runtime/locator.cjs`) — every `via`: `path` (an inherited PATH folder), `npm` (an npm package's bin/claude.exe, found by a folder's shims or its node_modules), `platform-package` (the platform package's copy behind npm's placeholder), `local-bin` (~/.local/bin, the native installer), `claude-local` (~/.claude/local, the legacy local install), `winget` (WinGet's links), `registry-path` (a folder only the stored Windows PATH has), `system` (/opt/homebrew/bin, /usr/local/bin, /usr/bin)
- `REQUIRED` (`electron/features/claude-runtime/locator.cjs`) — the oldest Claude Code the native path runs
- `mergePath` (`electron/features/claude-runtime/path-env.cjs`) — the PATH merge above: `mergePath(inherited, [machine, user], env)`
- `createResolver` (`electron/features/claude-runtime/resolver.cjs`) — `{ facts, observe, generation, observeCli, trackCli, checkCli, refresh, claimTrial, reset, subscribe, close }` over injected `keySaved`, `keyVersion`, `inspectCli`, `now`, `timers` and `stat`. `facts(scope, card)` lists what holds for a session of that project and card: `key` (`no_key`, or `invalid_key` held until the key changes when the connection test saw it, for a minute when a session did; the key's, every project), `cli` (the last check: `native_cli_required`, `cli_too_old`, `native_cli_unverified`), `billing` (`billing_identity_mismatch` for the project while its settings chain and the key are unchanged), `limit` (`credits_exhausted` or `account_limit`, the key's, with one ten-minute `trial` from `claimTrial`) and `rate` (a card's final rate limit for a minute, whose end is told to subscribers). `observe({ kind: 'failure'|'identity'|'success'|'key', scope, observed, … })` takes what a session or the connection test saw under `generation()`; an older generation changes nothing. The file also exports `cliFact`, `testFacts` (a test's own answers, which stand in for the held facts for that answer only), `overlay` and `settingsChain`
- `decide` (`electron/features/claude-runtime/decide.cjs`) — `decide(facts, settings, { agent, owner, trial, retained, running }) → { path, reason, wire, message, blockers }`: `path` is `api`, `terminal`, `native` (Codex) or null (refused); `reason` the first blocking fact's Reason (`claude.terminal_selected` for terminal-only), `wire` what the windows are told for it today, `blockers` every blocking Reason. A worker is not stopped by the owner's credits, a claimed trial passes its own limit, a running session's CLI is not in question and under API-only a running session meets a provider limit on the API. Also exports `excused` and `nameOf`
- `readStoredPath` (`electron/features/claude-runtime/path-env.cjs`) — the stored machine and user PATH as `[machine, user]`, read (never written) by the PowerShell under the environment's SystemRoot within five seconds; null when it cannot be read or the environment has no SystemRoot

## Not ours
- Running the CLI, its version requirement's wording, the connection test and the sessions that report what they saw — Claude SDK runtime (`electron/features/claude-sdk/**`)
- Acting on a decision: starting, switching and refusing sessions — Native session router (`electron/features/native-session/**`)
- The terminal wrappers that read the choice — `integration/bootstrap.ps1`, `integration/bash-integration.bash`, `integration/zsh-integration.zsh`, `integration/refresh-path.ps1`
- Telling a terminal its choice, refreshing on start-up and window focus — `electron/main.cjs`
