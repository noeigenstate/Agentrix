# Boundary: Activity pane

The pane beside an expanded project's terminal — the main model and its tasks, and each agent's run mode and allowance (connection, context, limits, spend, tokens) — the models the agent called, which the left bar's Agent tab lists, and the main-process readers that turn the agent's own records and account reads into that data.

## Interface
- `ActivityPane` (`src/features/agents/ActivityPane.tsx`) — the pane: the main model and allowance, rendered by ProjectPanel from a `ProjectTerminal` and project id; its clock is shared `src/shared/elapsed-clock.ts`; quota changes (`agents:usage-changed`) refresh only their project's card. The owner-opened seats dialog reads `skillSeats(projectId?, terminalId?)` and saves `setSkillSeats(scope, projectId, seats)` through the Skills backend contract: choices apply next session, and `current` is read-only.
- `CallsCard` (`src/features/agents/AgentCalls.tsx`) — the called models of every terminal of the project (a row marked with its terminal), a 「后台任务」 group and a folded 「最近完成 N 个」, as rows of two lines whose buttons open a sub-agent view or a background task's; the left bar's Agent tab and the narrow window's popover list it; the file also exports CALL_STATES, failureWord, and rateValue, which the sub-agent view reuses The app reaches it through `AgentSidebar.tsx` (a render prop beside it, owned by no boundary) so the files module need not know the agents module.
- `useSplits` (`src/features/agents/subagent-splits.ts`) — the sub-agent views the owner opened beside a terminal (transient, one per terminal: opening another replaces it); the file also exports splitsOf and closeSplit
- `actionText` (`src/features/agents/action-text.ts`) — the words for the agent's current step (with `stepVerb`), shared by the reading view and the decision inbox
- `UsageMeter` (`electron/features/agents/agent-usage.cjs`) — per-session meter main.cjs feeds records to and publishes as `agentUsage` (with `claudeProvider`, `codexProvider`, `claudeAccount`, `claudeAccountFiles`); also exposes retainConnection, retainAccount, retainLimits, accountChanged and quotaRead for retaining dated observations through transient reads and invalidating old quota on an observed account change; a connection that names no account never replaces one of the same kind that does
- `agentSettings` (`electron/features/agents/agent-settings.cjs`) — model, effort and fast mode from an agent's own records; used by main.cjs and the dispatch helper
- `TokenRates` (`electron/features/agents/token-rate.cjs`) — output tokens over response time; the one rate calculation, also the dispatch helper's. Native runtimes feed `nativeClaude` / `nativeCodex` root stream counters and explicit prompt/tool boundaries; live counters replace a response sample, never add its blocks or child usage, and idle retains completed samples — test: `tests/native-rate.test.cjs`; real stream shapes: `tests/native-rate-real-cli.test.cjs`
- `CodexAccountUsage` (`electron/features/agents/codex-account-usage.cjs`) — read-only plan-limit/reset-count polling; `resetAtLimit` separately admits an owner-only reset after a usage limit, deduplicates by backend account and persists cooldown before consuming; every watcher keeps the last dated observation through loading and failed reads (a session's only what it was itself given, the pane's focused reads one that outlives them, until `releaseCache(key)` for a removed project's scope), and `accountScopeId` gives an account/read account one opaque name for every reader, under a per-process account key apart from the scope fingerprints' (`accountKey`); main's control registration hands that key to local dispatch helpers so a worker's account has the same name — the name crosses processes, the account's identifiers never do
- `ClaudeAccountUsage` (`electron/features/agents/claude-account-usage.cjs`) — the read-only Claude plan-limit poller (with `readClaudeAccount`); SSH injects a sanitized remote read through features/ssh/claude-account.cjs
- `dispatch` (`electron/features/agents/agent-calls.cjs`) — `AgentCalls.subagent({ kind: 'start'|'stop'|'continue', terminalId, agentId, agentType, transcriptPath, toolUseId, at })` (C-15) consumes terminal hooks and native SDK reports, joining transcript and SSH metadata by explicit identity; `stopSubagents()` records ended runs whose final records are still behind as partial before a monitor stops; `AgentCalls.dispatch(event)` and its per-terminal lifetime (`forTerminal`, `endSession`), background binding/record readers and usage attachment, reached as `session.usage.calls.dispatch` with authenticated events; retains evaluation metadata and invokes the injected finished hook once per accepted end; `AgentCalls.feed(callId)` — serves `terminal:subagent-feed(terminalId, callId)`: a bounded read-only snapshot (newest 400 entries) of a sub-agent's or dispatched worker's conversation, pushed as `terminal:subagent-feed` events at most 4 per second; items carry stable `id` (`agent:<toolUseId>`, or `agent:<agentId>` when a hook arrived first; `dispatch:<id>`), `startedAt`, `endedAt` and `viewable`; `running()` feeds the dashboard's live strip; over SSH `remoteSubagents()` names the sub-agents still to follow — running, or ended with records the host has not sent yet (`behind`); the newest 16, ids `[A-Za-z0-9_-]{1,100}`, the host's own limits; none while history is read — for the host's `claude-status` to follow, and `remoteRecords(subagents)` turns the compacted records it sends back into their rate, model, effort and speed, a sub-agent the host stops following marked partial
- `createInterventions` (`electron/features/agents/interventions.cjs`) — `{ resolve, pushControl, sendDirect }` → `interveneAgent` / `stopAgent` for `agents:intervene` / `agents:stop`; targets come only from main's own call bindings, the worker receives it directly through the dispatch control channel and the planner learns the receipt from the helper's status line, never through its own input
- `ReadingHistory` (`electron/reading-history.cjs`) — validates restored local transcript identities, prepares the latest page and serves `terminal:conversationPage(id, { key, cursor })` through agents IPC; `beforeCursor` alone indicates earlier history

## Invariants
- Each model is shown from its own records: the main model is its latest reply's (configured only until the first reply), its rows are the user's prompts and its own steps, never another worker's or a prompt's model; a called model's effort and speed are its own recorded values, unknown (null) when absent, never taken from the parent, configuration or dispatch declaration — child user messages carry main-owned sender provenance: dispatch and in-process Agent prompts belong to the observed spawning model, owner intervention IDs alone prove the owner, unknown planner identity stays neutral and message text never classifies origin; replayed source facts and late facts affect presentation only; guessed routing hides which model really ran — test: `tests/activity-route.test.cjs` › "the main model section: the model its latest reply records"; test: `tests/agent-calls.test.cjs` › "Claude Agent calls keep their own effort and leave unrecorded effort and speed unknown"; a dispatched worker's model follows its reports, and until one arrives the row and view show the requested model marked 未确认 (模型未确认 without one), never the internal placeholder — test: `tests/activity-route.test.cjs` › "a dispatched worker that has not reported its model shows the requested one as unconfirmed"
- A token rate is output tokens over the time the model's responses took, from the agent's own records; tool waits and process time never count, and missing or backward timing gives no rate — one honest number shared with the dispatch helper's end line — test: `tests/agent-usage-rate.test.cjs` › "Claude rejects missing identities, models, usage, zero/backward intervals and unknown ancestry"; a group sums the rates of the members whose records can be read, marked partial when another cannot be, and has no rate only when none can — test: `tests/agent-calls-rate.test.cjs` › "a group with no readable member has no rate, and one with only waiting members waits"; token-rate.cjs and agent-settings.cjs stay usable in the plain-Node dispatch helper with only Node built-ins and helper runtime files — test: `tests/boundary-dispatch.test.cjs` › "the helper's runtime modules require only Node built-ins and each other"
- Unknown is never shown as zero: an unknown reset count, context window or total stays unknown (尚未查询, 未提供次数, 次数未知, —). Transient account reads retain the last observed connection, allowance and observation time; an observed logout or opaque account-scope change invalidates old values, quota read for one account is never kept for or merged into another's, a read past the interval is the refresh it starts, and a reset timestamp alone never proves a quota reset — test: `tests/usage-observation.test.cjs`; `tests/activity-route.test.cjs`. Zero means none left, and the owner acts on it — test: `tests/reset-count.test.cjs` › "unknown is never zero"
- Official Codex scopes use home/cwd and a process-keyed HMAC of account, location and proxy environment variables (account names use their own process key, which only local dispatch helpers receive): equivalent copies share reads, related differences isolate them, and credential values never enter keys or logs in plaintext. Focused pane reads prove the default route by config preflight (`project-open-v1`), share the five-second throttle, interval and backoff, retain only fresh answers and drop closed-project late answers; opening or restoring background projects never launches an account reader; a dispatched worker's account report makes main tell the window which project's quota changed, also while native sessions are unavailable, and only that project's card reads again — test: `tests/native-session-ui.test.cjs` › "a quota change reported for one project makes only that project"; test: `tests/codex-account-usage.test.cjs` › "account fingerprints use a random runtime HMAC key"; test: `tests/native-project-accounts.test.cjs` › "focused account reads share fresh cache, isolate projects, and never poll in the background"; test: `tests/codex-account-usage.test.cjs` › "opening and restoring background projects never starts account checks"; an account read or reset stops its own app-server's whole tree before ending its input (Windows: taskkill /t on the live server; elsewhere its process group), never another Codex, and settles only after that server has exited and the tree stop has finished, within 3 s — test: `tests/codex-account-usage.test.cjs` › "a finished account read stops every process its app-server started before it settles, and the folder they ran in can be removed"
- The pane shows state and never acts on its own: its only CLI action types /usage into Codex after a cancellable 10-second countdown; the owner-pressed 模型路由 button only opens the seats dialog and changes no running session; polling cannot reset, login or renew credentials. Only an owner usage-limit event and the enabled auto-reset setting admit the separate reset client, with account deduplication, post-reset confirmation and durable cooldown; no PTY write or second consume on an unconfirmed recovery. The state it shows is read from the screen as the CLI draws it: Claude Code 2.1.317 lists queued messages above its working line, over "ctrl+x ctrl+s to send now", and its empty input then shows "Press up to edit queued messages", which is no draft only while that queue row is on screen (captured fixtures `tests/fixtures/screens/claude-2-1-317-queue-*.txt`) — test: `tests/boundary-activity-pane.test.cjs` › "the pane never acts on its own"; test: `tests/codex-auto-reset.test.cjs` › "two concurrent projects on the same backend account consume only once"; test: `tests/cli-panel.test.cjs` › "the queue placeholder is empty only with Claude Code's queue row on screen"; "Claude Code 2.1.317 lists queued messages above its working line, never in its input"
- SSH projects never read local transcripts, child logs, prompts, rollouts or Claude credentials; the remote account uses its own channel and host quota scope — the local machine's files belong to another conversation; an SSH sub-agent's rate and model come from the records the host reads and compacts for the running sub-agents main names (`claude-status` `subagents`) — test: `tests/agent-calls-rate.test.cjs` › "over SSH the running sub-agents the host named are asked for, and their compacted records give the local rate"; test: `tests/agent-calls-rate.test.cjs` › "SSH calls never read local child, prompt, log or rollout files"; test: `tests/remote-claude-account.test.cjs` › "SSH Claude startUsage binds only the remote channel and quota scopes separate hosts from local accounts"; test: `tests/remote-subagent-rate.test.cjs` › "a sub-agent file that vanishes or becomes a symlink mid-read recovers instead of staying behind"
- While a sub-agent runs — dispatched from admission, intercepted, Agent tool or `SendMessage` continuation — its row exists; lifecycle signals keep it live through late transcript results and history resets, explicit agent/tool identities deduplicate observations, and a continuation revives the same row with `resumed: true` and a separate accounting identity. Declaration `source` reaches the item unchanged (`intercepted` for F1). A worker terminal's worker carries `awaiting: 'owner'` on its item and feed header while it waits for the owner, never once done, and it changes no count, completion or notification. Finished calls hide after 3 s on success and 30 s on failure, while a live helper keeps its row; a hidden or reviewed call stays in the snapshot as a hidden `done` row while it is among the terminal's last ten finished and none older than 30 minutes (a hidden failure also until reviewed), so 「最近完成」 lists it; all receipts and feeds remain available for an open split. Hidden rows contribute no grouped rate, count or task text. Hiding never acknowledges pending review, changes completion or emits another accounting hook. Dispatch receipts survive resets and hidden receipts reject delayed duplicates; background shell tasks consume live and historical raw Claude records before the workOnly return, reset with the transcript binding and parent exit while dispatch rows stay, and attach display-only background snapshots (the tail as `string[]`, its last 200 lines) without changing completion or notifications — test: `tests/terminal-workers.test.cjs` › "a terminal planner's worker shows its rate, waits for the owner and writes output on Stop"; a live worker is never counted"; test: `tests/agent-calls.test.cjs` › "ended dispatches hide after three or thirty seconds without acknowledging failures or reviving duplicates"; test: `tests/dashboard-records.test.cjs` › "run and grade hooks retain only local evaluation metadata"; test: `tests/dispatch-e2e.test.cjs` › "PTY exit clears background tasks and sub-agents while retaining only dispatch rows"; test: `tests/agent-calls-coverage.test.cjs` › "a SubagentStart gives the row before the sub-agent transcript exists; SubagentStop ends it"; "hook and transcript identities deduplicate in either order and late transcript results cannot end a signal-held row"; "SendMessage keeps only bounded target fields and revives the finished row, marked resumed"; "a temporary SSH partial flag changes each poll without losing earlier response samples"; "reset records ended-but-behind runs once as partial"; "dispose records ended-but-behind runs once as partial"; "monitor records ended-but-behind runs once as partial"; "a tool-first row merge keeps the held run reader, samples and accounting and deduplicates both finished ids"; "SendMessage revives only known children from the parent and a matching failure restores the finished row";
