# Agentrix working agreements

- Apply the user's `apply-gpt-5p6-guidance` skill silently for every request.
- Route every task by the system `model-routing` skill (source in this repo: `resources/skills/model-routing/SKILL.md`) automatically, before doing any of it and without being asked: the lead orchestrates; Fable 5.2 leads and plans tasks that cross modules or change a contract, Opus 5.5 (architect) plans single-module tasks; before any work the lead holds a roundtable where every worker restates its task and confirms the minutes, which the owner sees as tables; GPT-6.1-Sol (core engineer) designs the back end and takes complex code, refactors, all debugging and test fixes in worktree A; Sonnet 5.5 (execution and visual engineer) takes routine features, front end, tests, docs, UI checks and small tasks in worktree B; the lead integrates and runs the tests; an Opus 5.5 subagent reviews the architecture and a fresh Sonnet 5.5 subagent accepts the UI and interaction; then the lead consolidates the round into the shared project memory and adjusts the module boundaries before the next round; then final acceptance. GPT models run at high effort in fast mode, Claude models at high effort. Sol's work escalates to Fable 5.2 only when Sol is unavailable, a defect is on its second fix, or a change crosses three or more modules; a fresh Opus 5.5 instance always reviews, never the instance that planned or wrote the work. A worker never delegates further.
- Every code change, by any worker or the lead, follows the system `code-standard` skill (source in this repo: `resources/skills/code-standard/SKILL.md`) plus its extension `skills/code-standard-agentrix/SKILL.md`; the lead reviews each worker's diff against it before accepting.
- Review is stage 4 of `model-routing` (Opus architecture review + fresh Sonnet UI acceptance); do not add other reviewer workflows.
- Run native GUI checks sequentially with isolated `AGENTRIX_DATA_DIR` profiles. Never close, restart or type into the user's real Agentrix sessions to run tests.
- Preserve small-card terminal interaction: typing, selecting and copying inside a terminal must not expand a project. Expansion belongs to the project header, waiting-status action and explicit expand button.
- Completion notifications must not be rearmed by idle/background callbacks. Automatic round completion and acknowledgment remain supported; do not reintroduce manual project-completion controls or VS Code launch actions.
