# Agentrix working agreements

- Apply the user's `apply-gpt-5p6-guidance` skill silently for every request.
- Route every task by the system `model-routing` skill (source in this repo: `resources/skills/model-routing/SKILL.md`) automatically, before doing any of it and without being asked: the lead is the Orchestrator and schedules the team seats set in Agentrix's model routing (Product, Architect, Designer, Developer, Reviewer, QA, Researcher, DevOps, Security); independent work runs in parallel (Product with Researcher, Architect with Designer, Developer specialties in separate worktrees, Reviewer with QA and Security); before any build the lead holds a roundtable where every worker restates its task and confirms the minutes, which the owner sees as tables; the lead integrates and runs the tests; fresh Reviewer and QA instances that neither planned nor wrote the work review the code and accept the UI and interaction, and Security audits new permission, file-read, process and dependency surfaces; DevOps runs only for a requested release; then the lead consolidates the round into the shared project memory and adjusts the module boundaries before the next round; then final acceptance. Seats decide each worker's model, effort and fast setting; an explicit instruction from the owner in the conversation wins for that task only, and the Orchestrator states the deviation in its plan. A worker never delegates further.
- Every code change, by any worker or the lead, follows the system `code-standard` skill (source in this repo: `resources/skills/code-standard/SKILL.md`) plus its extension `skills/code-standard-agentrix/SKILL.md`; the lead reviews each worker's diff against it before accepting.
- Review is stage 5 of `model-routing` (fresh Reviewer, QA and Security); do not add other reviewer workflows.
- Run native GUI checks sequentially with isolated `AGENTRIX_DATA_DIR` profiles. Never close, restart or type into the user's real Agentrix sessions to run tests.
- Preserve small-card terminal interaction: typing, selecting and copying inside a terminal must not expand a project. Expansion belongs to the project header, waiting-status action and explicit expand button.
- Completion notifications must not be rearmed by idle/background callbacks. Automatic round completion and acknowledgment remain supported; do not reintroduce manual project-completion controls or VS Code launch actions.
