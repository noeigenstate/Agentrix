# Boundary: Intercept

A planner's tool-shell calls to Codex exec and Claude print mode enter the existing dispatcher through PATH shims. Only a planner's environment has the shims: the owner's own shell, scripts and typed commands keep their real CLI path.

## Owns
- `integration/shims/**`

## Interface
- `mapCommand` (`integration/shims/intercept.cjs`) — the C-8 whitelist, structured options or a named refusal before admission.
- `intercept` (`integration/shims/intercept.cjs`) — reroute a planner's delegation through the existing helper with source intercepted, run any other planner call as the real CLI, refuse a worker's call as nested.
- `withShims` (`integration/shims/intercept.cjs`) — clone an environment, prepend the installed shim folder once, set depth plus the worker's opaque run identity, and add the start-up hooks that keep the folder first; depth zero removes worker identity.
- `shimWords` (`integration/shims/intercept.cjs`) — what withShims changes, as env(1) words; the terminal wrappers start their Claude Code with them (`intercept.cjs --shim-env`).
- `runtimeFiles` (`integration/shims/intercept.cjs`) — the Node-only intercept module and a CJS envelope of the six source launchers and marker; shimFiles reads the same source assets for packaging.
- `hookFiles` (`integration/shims/intercept.cjs`) — the start-up hooks (BASH_ENV, CLAUDE_ENV_FILE, zsh ZDOTDIR stubs) the packaged app installs beside the launchers; a session gets its own copy of the CLAUDE_ENV_FILE hook (bootstrap-file.cjs).

## May import
- `integration/dispatch.cjs` (the helper's public run function and its CLI locators)

## Invariants
- A planner's mappable codex exec (alias e) or Claude print call enters the existing helper with source intercepted and keeps its CLI's default read-only permission, writing only through --sandbox workspace-write, --full-auto or --permission-mode acceptEdits; piped input joins a prompt argument as that CLI joins it; anything else is refused by name before execution, with an equivalent command when the remaining options map — test: `tests/dispatch-intercept.test.cjs` › "a call keeps its CLI's default read-only permission and writes only through the explicit write flags"; test: `tests/dispatch-intercept.test.cjs` › "an unsupported option is refused by name with the equivalent command and exit code 2"; test: `tests/dispatch-intercept.test.cjs` › "piped input joins a prompt argument as each CLI joins it"; test: `tests/dispatch.test.cjs` › "a dispatched CLI inherits shim depth and signed identity while its declaration keeps intercepted".
- A planner's call that is not a delegation (codex mcp-server, claude mcp serve, --version, login status) runs the real CLI found outside the shim folder, with inherited streams and its exit status; both locators exclude a folder containing .agentrix-shims, and the helper never launches a bare codex — test: `tests/dispatch-intercept.test.cjs` › "at depth zero a call that is not a delegation runs the real CLI"; test: `tests/codex-runtime-guards.test.cjs` › "the Agentrix shim folder is never a locator candidate, for Claude or Codex"; test: `tests/dispatch.test.cjs` › "no session, timeout and spawn failure print failed-start once and end unconfirmed".
- A call fails closed as nested, before stdin, lookup or dispatch, when its depth is missing or not zero, when it carries a worker's run identity or proof, or when it has no bootstrap; a worker still runs the CLI's version and help. A Codex planner whose shell_environment_policy is inherit="core" drops AGENTRIX_* but keeps PATH, so its calls are refused as nested by design — test: `tests/dispatch-intercept.test.cjs` › "a call without a planner's depth zero and bootstrap, or with a worker identity, is refused as nested"; test: `tests/dispatch-intercept.test.cjs` › "a worker runs only version and help".
- Stdout carries only the final message, stderr carries dispatcher reports, and exit status is zero for success, one for failure and two for refusal; a failed cleanup after a printed answer keeps exit zero — test: `tests/dispatch-intercept.test.cjs` › "a rerouted stdin call uses the helper, declares intercepted, and prints only its final message"; test: `tests/dispatch-intercept.test.cjs` › "helper failures become exit one and cannot mix dispatch reports into stdout".
- Only the Claude Code an owner's terminal wrapper starts, a native owner session and a dispatched worker get the shims; the terminal's own PATH, its scripts and its other commands never do, nor an owner's ! command in a native session (Claude runs it with the session's owner env; Codex runs it behind ownerShellCommand's first line, sent only to a shell it is written for: bash, zsh, sh, dash or ksh from passwd, or PowerShell on Windows, skipped outside FullLanguage mode; fish, cmd or an unknown shell runs the text as typed, with the shims). The planner sees that line in its history and could copy it to skip forced dispatch, which is no worse than calling the real CLI by path: interception is routing, not enforcement, nor the terminals of an Agentrix started inside a planner, which get the user's own hooks back — test: `tests/dispatch-intercept.test.cjs` › "the PowerShell terminal's PATH has no shims and the claude it starts has them first at depth zero"; test: `tests/dispatch-intercept.test.cjs` › "terminal's PATH has no shims and the claude it starts has them first at depth zero"; test: `tests/dispatch-intercept.test.cjs` › "interactive wrappers read bootstrap shims, keep real CLI lookup outside that folder".; test: `tests/dispatch-intercept.test.cjs` › "an owner terminal started inside a planner has no shim variables"; test: `tests/native-parity-review.test.cjs` › "an owner's ! command runs with the session's owner env"; test: `tests/dispatch-intercept.test.cjs` › "an owner's ! command in a native Codex session runs the real CLI"; test: `tests/dispatch-intercept.test.cjs` › "the owner-command line goes only to a shell it is written for"
- Inside a planner the shims stay first after the user's start-up files reorder PATH: BASH_ENV for bash, ZDOTDIR stubs for zsh and CLAUDE_ENV_FILE after Claude Code's shell snapshot, each running the user's own hook first and never one that is an Agentrix hook by location (a shim folder or a session's copy), so a planner inside another Agentrix's planner cannot recurse; CLAUDE_ENV_FILE is the session's private copy, never an installed file (G13) — test: `tests/dispatch-intercept.test.cjs` › "login shell whose profile puts a stand-in CLI first, a planner's codex exec and claude -p reach the intercept path"; test: `tests/dispatch-intercept.test.cjs` › "withShims adds start-up hooks that run the user's own first and never chain to themselves".; test: `tests/dispatch-intercept.test.cjs` › "a planner inside another Agentrix's planner keeps the user's own hooks"; test: `tests/dispatch-intercept.test.cjs` › "a planner's CLAUDE_ENV_FILE is the session's private copy"
- The carried launcher envelope contains the same six source launchers and marker, with CJS names that preserve the SSH transport contract, and the packaged folder also holds the start-up hooks; remote shim activation remains deferred; the PowerShell launchers pass every word as a string — test: `tests/boundary-dispatch.test.cjs` › "the carried intercept runtime includes the six launchers in a CJS envelope"; test: `tests/dispatch-intercept-real-cli.test.cjs` › "installed launchers preserve quoted Unicode arguments and stdin through the host shells".
- Owner environments start at depth zero and discard an inherited worker identity; worker environments hold a per-run HMAC proof without the reporting credential — test: `tests/dispatch-intercept.test.cjs` › "withShims preserves the caller environment and sets one PATH, depth and opaque run identity"; test: `tests/dispatch.test.cjs` › "a dispatched CLI inherits shim depth and signed identity while its declaration keeps intercepted".
