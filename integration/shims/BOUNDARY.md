# Boundary: Intercept

A planner's tool-shell calls to Codex exec and Claude print mode pass through PATH shims. Native mode runs them on the real CLI. Conductor mode directs the planner to the role tools. The owner's shell, scripts and typed commands keep their real CLI path.
The MCP command carries the lead provider and, for a Claude terminal with a saved lead seat, its launch model and effort.
The owner terminal opens a native session for bare `agy` and forwards invocations with CLI arguments to the installed agy executable.
In a planner shell, the terminal adapter declares agy invocations with arguments as delegations, with version and help available in either mode.

The structured launch migration uses `agentrix.launch-route` for classify, typed NUL-terminated records for words,
and `launch.words` JSON for PowerShell. It reads the new session mode through `readSessionMode`.

## Owns
- `integration/shims/**`

## Interface
- `intercept` (`integration/shims/intercept.cjs`) — run a planner's permitted calls on the real CLI, attach role tools to conversations and refuse shell delegation in conductor mode. Workers can only ask for version or help.
- `withShims` (`integration/shims/intercept.cjs`) — clone an environment, prepend the installed shim folder once, set depth plus the worker's opaque run identity, and add the start-up hooks that keep the folder first; depth zero removes worker identity.
- `shimWords` (`integration/shims/intercept.cjs`) — what withShims changes, as env(1) words; the terminal wrappers start their Claude Code with them (`intercept.cjs --shim-env`).
- `roleToolArgs` (`integration/shims/intercept.cjs`) — the arguments that attach the role-tool server (`dispatch.cjs mcp`) to a lead's conversation, with the planner environment for the server; for Claude Code one word (`--mcp-config=<json>`), so a prompt after it stays the prompt. intercept puts them before a planner's own conversation call, and the terminal wrappers get them in the same answer as the planner's words (`intercept.cjs --shim-env [json] --role-tools <agent> <the user's arguments>`, after a `--` word; the request may come in AGENTRIX_INTERCEPT_ARGV): none for a delegation (print mode, codex exec) or a call that opens no conversation, by intercept's own rule. Bash, zsh and PowerShell executable launches pass the inline word. PowerShell launches of .cmd and .ps1 use `--mcp-config=<file>` and clean up the per-launch config. A failed request leaves the launch as it was.
- `runtimeFiles` (`integration/shims/intercept.cjs`) — the Node-only intercept module and a CJS envelope of the nine source launchers and marker; shimFiles reads the same source assets for packaging.
- `terminalLaunch` (`integration/shims/intercept.cjs`) — `--launch` classifies terminal calls and returns environment words and argv. The envelope carries the adapters for packaged and SSH runs.
- `hookFiles` (`integration/shims/intercept.cjs`) — the start-up hooks (BASH_ENV, CLAUDE_ENV_FILE, zsh ZDOTDIR stubs) the packaged app installs beside the launchers; a session gets its own copy of the CLAUDE_ENV_FILE hook (bootstrap-file.cjs).

## Invariants
- Shell and helper format readers stay within the module baseline — test: `tests/self-format-guard.test.cjs` › "product and test text readers match the per-module self-format baseline"
- Shell delegation runs on the real CLI in native mode and is refused with exit code 2 in conductor mode. Interactive planner conversations get the role tools in both modes — test: `tests/dispatch-intercept.test.cjs` › "native mode runs a delegation on the real CLI and conductor mode refuses it; an interactive lead gets the role tools in both"
- A planner's call that is not a delegation (codex mcp-server, claude mcp serve, --version, login status) runs the real CLI found outside the shim folder, with inherited streams and its exit status; both locators exclude a folder containing .agentrix-shims, and the helper never launches a bare codex — test: `tests/dispatch-intercept.test.cjs` › "at depth zero a call that is not a delegation runs the real CLI"; test: `tests/codex-runtime-guards.test.cjs` › "the Agentrix shim folder is never a locator candidate, for Claude or Codex"; test: `tests/dispatch.test.cjs` › "no session, timeout and spawn failure print failed-start once and end unconfirmed".
- A call fails closed as nested, before stdin, lookup or dispatch, when its depth is missing or not zero, when it carries a worker's run identity or proof, or when it has no bootstrap; a worker still runs the CLI's version and help. A Codex planner whose shell_environment_policy is inherit="core" drops AGENTRIX_* but keeps PATH, so its calls are refused as nested by design — test: `tests/dispatch-intercept.test.cjs` › "a call without a planner's depth zero and bootstrap, or with a worker identity, is refused as nested"; test: `tests/dispatch-intercept.test.cjs` › "a worker runs only version and help".
- Only the Claude Code an owner's terminal wrapper starts, a native owner session and a dispatched worker get the shims; the terminal's own PATH, its scripts and its other commands never do, nor an owner's ! command in a native session (Claude runs it with the session's owner env; Codex runs it behind ownerShellCommand's first line, sent only to a shell it is written for: bash, zsh, sh, dash or ksh from passwd, or PowerShell on Windows, skipped outside FullLanguage mode; fish, cmd or an unknown shell runs the text as typed, with the shims). The planner sees that line in its history and could copy it to skip forced dispatch, which is no worse than calling the real CLI by path: interception is routing, not enforcement, nor the terminals of an Agentrix started inside a planner, which get the user's own hooks back — test: `tests/dispatch-intercept.test.cjs` › "gives claude.${extension} one file-backed role option, hook settings and a clean shell"; test: `tests/dispatch-intercept.test.cjs` › "terminal's PATH has no shims and the claude it starts has them first at depth zero"; test: `tests/dispatch-intercept.test.cjs` › "interactive wrappers read bootstrap shims, keep real CLI lookup outside that folder".; test: `tests/dispatch-intercept.test.cjs` › "an owner terminal started inside a planner has no shim variables"; test: `tests/native-parity-review.test.cjs` › "an owner's ! command runs with the session's owner env"; test: `tests/dispatch-intercept.test.cjs` › "an owner's ! command in a native Codex session runs the real CLI"; test: `tests/dispatch-intercept.test.cjs` › "the owner-command line goes only to a shell it is written for"
- Inside a planner the shims stay first after the user's start-up files reorder PATH: BASH_ENV for bash, ZDOTDIR stubs for zsh and CLAUDE_ENV_FILE after Claude Code's shell snapshot, each running the user's own hook first and never one that is an Agentrix hook by location (a shim folder or a session's copy), so a planner inside another Agentrix's planner cannot recurse; CLAUDE_ENV_FILE is the session's private copy, never an installed file (G13) — test: `tests/dispatch-intercept.test.cjs` › "login shell whose profile puts a stand-in CLI first, a planner's codex exec and claude -p reach the intercept path"; test: `tests/dispatch-intercept.test.cjs` › "withShims adds start-up hooks that run the user's own first and never chain to themselves".; test: `tests/dispatch-intercept.test.cjs` › "a planner inside another Agentrix's planner keeps the user's own hooks"; test: `tests/dispatch-intercept.test.cjs` › "a planner's CLAUDE_ENV_FILE is the session's private copy"
- The carried launcher envelope contains the same nine source launchers and marker, with CJS names that preserve the SSH transport contract, and the packaged folder also holds the start-up hooks; remote shim activation remains deferred; the PowerShell launchers pass every word as a string — test: `tests/boundary-dispatch.test.cjs` › "the carried intercept runtime includes the nine launchers in a CJS envelope"; test: `tests/dispatch-intercept-real-cli.test.cjs` › "installed launchers preserve quoted Unicode arguments and stdin through the host shells".
- Owner environments start at depth zero and discard an inherited worker identity; worker environments hold a per-run HMAC proof without the reporting credential — test: `tests/dispatch-intercept.test.cjs` › "withShims preserves the caller environment and sets one PATH, depth and opaque run identity"; test: `tests/dispatch.test.cjs` › "a dispatched CLI inherits shim depth and signed identity while its declaration keeps intercepted".
