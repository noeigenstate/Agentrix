# Boundary: Dispatch

The dispatch helper that every command-line Codex or Claude worker is started through — it builds the real command, confirms the worker started, and reports its routing, rate and end — and the main-process gate that accepts its events for the activity pane. Claude --fast reaches its CLI as a JSON settings argv element. Claude aliases accept their own family at the bundled CLAUDE_ALIAS_FLOOR (currently major 5, minor 5) or newer, ignoring date and context/speed suffixes; older versions remain mismatches. A release bump changes the one floor constant in routingVerdict; no caller option or environment variable sets it.

Codex workers registered through local dispatch control use the lead conversation's frozen operation config and report refused keys on a routing line.
Main delivers frozen Claude operation settings to its brokered workers. SSH-dispatched workers and direct Claude helper launches use agent defaults.
Local and SSH Claude terminal wrappers read the live lead file at launch, including the optional background and subagent model lines.
The sixth line carries the launch's seat choices. The helper uses a matching seat from that launch map for omitted model, effort and fast flags.
Claude's terminal Agent and Task hooks report provisional and final input by tool-use ID.
The local Codex helper can fill omitted seat flags from the private bootstrap's seat snapshot before dispatch registration.

## Interface
- `createDispatchControl` (`electron/features/agents/dispatch-control.cjs`) — the authenticated execution-control channel and its helper client, connectDispatchControl; registration refusals carry a closed code, and authenticated refusals also carry leadMode on the frame and client error.
- `resolveRegistration` (`electron/features/agents/dispatch-registration.cjs`) — main's current-session, worker-cwd board and lead-mode binding, or a coded refusal; test: `tests/dispatch-registration.test.cjs` › "a worker in a worktree registers against the board its helper admitted it on; a board from another Git common directory is refused with project_mismatch; a worker outside Git is bound from its authenticated declaration and no wider".
- `USAGE` (`integration/dispatch.cjs`) — the helper's command line (`node dispatch.cjs <codex|claude> … [--seat <id>[/<specialty>]] [--detach]`, `wait <run id> … [--timeout <s>] [--cwd <dir>]`, and `stop <run id> [--reason] [--no-resume]` for the planner to stop a worker whose owner intervention conflicts with its task); detached helpers retain receipts beside the team journal (standalone helpers use a per-directory temporary store), and wait returns 75 while runs remain active, otherwise 0 with worker exit codes in the end lines; receipts are advisory and main's signed events are authoritative, receipt replacement retries sharing violations without interrupting event delivery, and a per-run socket nonce distinguishes helper identity from PID reuse; a normal owner intervention never stops a worker: it is resumed in the same session after its current run; sessions learn its path from the startup note (skills/agent-dispatch)
- `[dispatch]` (`integration/dispatch.cjs`) — the started / failed to start / ended lines, and a Codex worker's request lines (opened, unanswered, resolution); events carry kind, meeting, the requested model and verified routing, and a model reported after the start follows as dispatch-routing; outputTokens/activeMs are the meter's timed pair and totalOutputTokens is the invocation's cost count; resumed Codex never falls back to stdout totals
- `runtimeFiles` (`integration/dispatch.cjs`) — the electron modules the helper carries; copied by scripts/after-pack.cjs and electron/remote-connection.cjs
- `acceptDispatch` (`electron/features/agents/dispatch-events.cjs`) — main.cjs hands it every dispatch-* event from a session's event pipe
- `createDispatchIntake` (`electron/features/agents/dispatch-intake.cjs`) — main's intake and per-terminal inbox binding/disposal for a session's dispatch-* events over the app shell's deps; holds the per-project dispatchAccounts, read by dispatchReading and cleared by clearDispatchAccount
- `dispatchAccount` (`electron/features/agents/dispatch-events.cjs`) — a Codex worker's dispatch-account report (its own app-server's account kind, observation time, account name and merged quota, read afresh for each report, sent only between dispatch-start and dispatch-end; an accepted report makes main send `agents:usage-changed` for the project) rebuilt from known fields as the limits payload an account read gives; acceptDispatch takes it only for a running Codex call and hands it to main's per-project store. The pane's Codex section uses it only when the project has no running Codex session and its own account read named no account, or named the same one; a report past two account intervals reads as stale. The name is made in the helper with main's account key, which the control registration gives only to local runs: without it (no control channel, an SSH run) the report names no account; account identifiers never leave the helper — test: `tests/dispatch-codex-usage.test.cjs` › "a dispatched Codex worker reports its app-server account and quota, and the pane shows them without a native session"
- `sessionContext` (`electron/features/skills/session.cjs`) — the Claude SessionStart command in agent-event.cjs emits context once per CLI session/fingerprint on startup/resume, always after compact/clear; other hooks remain silent
- `shellEvent` (`integration/agent-event.cjs`) — a Bash terminal's own reports, as zsh-integration.zsh sends them: shell-ready, shell-prompt, codex-started, codex-exited, and hook-channel (the claude wrapper fell back to command hooks; command names the proxy variable)
- `skillProposals` (`integration/dispatch.cjs`) — dispatch-end and the end line report the number awaiting the lead; versions live in `<out>.skill-proposals-<run id>/`

## Invariants
- A worker is known only from the helper's declarations, never shell commands, prompt filenames or stdout; events require the session's key at admission and project, well-formed fields and at most 16 KB, are persisted to the run's outbox, MAC'd and sequenced before main is woken, and are acknowledged and applied once; a declaration creates a starting row with an unconfirmed notice after 15 s without a start; a missing acknowledgment replays on a wake or the 60 s sweep without restarting the model request, and a terminal restart retains admitted-run authority without accepting another run under its earlier key; refusals count each (run, seq, code) once and log once per (run, code) without owner banners — dispatch-input records carry provider/session/input identifiers and channel origins, never message text; resumed owner inputs retain admitted owner control IDs, while initial/resumed helper briefs and minutes remain planner input. Source facts persist in the team journal and are validated by main; guessed routing is misleading and any local process can reach the pipe — test: `tests/dispatch-e2e.test.cjs` › "main preserves the admitted row and inbox across host restart and reports a forged late event by code"; test: `tests/dispatch-e2e.test.cjs` › "main binds delivery before launch and publishes the fifteen-second starting notice without a worker start"; test: `tests/dispatch-inbox.test.cjs` › "an unadmittable frame is counted once across wakes and sweeps and logged once per run and code"; test: `tests/dispatch-inbox.test.cjs` › "any order, duplication or loss of wake-ups applies each event once in seq order; a forged MAC or an unknown key is refused with its code"; test: `tests/dispatch-outbox.test.cjs` › "a failed wake retains signed events on disk and only an authenticated acknowledgment removes them"; test: `tests/dispatch-events.test.cjs` › "Bash commands, prompt filenames and helper stdout text never create or update a call"; test: `tests/dispatch-events.test.cjs` › "bad keys, projects, unknown ids, malformed fields and oversized payloads are rejected"
- What is declared is what runs: the helper builds the CLI's argv itself from its options, validates the optional seat and its specialty, carries it on both declaration and start events, and rejects unknown, repeated, missing or conflicting ones, and rejects absolute or parent-traversing --allow globs before admission — a loose option lets a worker run other settings than reported — test: `tests/dispatch.test.cjs` › "helper constructs exact Codex/Claude argv and rejects incomplete or ambiguous options"; test: `tests/dispatch-e2e.test.cjs` › "unsafe allow globs fail at argument parsing before admission or launch"
- "started" is printed and sent only from the worker's own records (its session, and Codex's turn context) within 30 s (60 s for a detached helper) — while it runs, or from everything it left once it exits — never from its exit alone; otherwise exactly one failed-start line and an unconfirmed start/end pair — the start line is the lead's proof the task ran, and a fast worker did run — test: `tests/dispatch.test.cjs` › "a worker that exits right after its records is confirmed from them; without them it still failed to start"; test: `tests/dispatch-detach.test.cjs` › "detached helper uses an independent process group, file stdio and the original start receipt"
- Reported routing is what the worker's own records say; a reported mismatch names the declaration and a missing value stays unreported and is marked unverified, and an unreported model gives an unverified verdict, never borrowed from the declaration or config — routing mistakes must be visible — test: `tests/dispatch.test.cjs` › "reported mismatches and missing settings never borrow the declaration"; Codex app-server's own thread, settings and reroute reports count as its records — test: `tests/dispatch.test.cjs` › "a model app-server reports after the start reaches the called-models row and replaces the placeholder"
- Helpers and hooks never wait for Agentrix's events, and a helper waits for main's control registration at most 2 s, and a refused registration is told by its code; an authenticated native-lead refusal fails a Claude worker's startup without launching the subscription CLI, while Codex keeps running without execution control; SessionStart can deliver without a live pipe, startup instructions and the manifest fallback stay on the command line, and only skills use the hook; a Codex worker's blocking request that nobody answers within 10 minutes is refused without approving it or interrupting its turn — reconnecting the app cannot lose instructions or duplicate delivery, and an unattended run cannot stall; the first event the pipe cannot deliver prints one line, `[dispatch] events not delivered to Agentrix (<errno or timeout>)`, once per process — test: `tests/dispatch.test.cjs` › "a pipe that cannot be reached is said once on the worker’s output and the worker still runs"; test: `tests/dispatch.test.cjs` › "without bootstrap or with a stalled pipe the worker still runs and finishes promptly"; test: `tests/dispatch-control.test.cjs` › "a registration main verifies within 2 s succeeds: neither the helper wait nor the channel idle limit cuts it short"; test: `tests/skills-session.test.cjs` › "Node SessionStart writes one JSON context even without Agentrix; other hooks remain silent"; test: `tests/dispatch.test.cjs` › "a blocking worker request is declined after the timeout and the worker finishes"; test: `tests/dispatch-control.test.cjs` › "registration rejection reports the failed binding without exposing credentials"; test: `tests/dispatch-startup.test.cjs` › "a Codex worker under a native lead still starts after a project-mismatch control refusal"
- Everything the helper loads from electron/ is carried in runtimeFiles and requires only Node built-ins and other carried files — plain Node cannot read app.asar and an SSH host has only the copies — test: `tests/boundary-dispatch.test.cjs` › "the helper's runtime modules require only Node built-ins and each other"
- Tests start workers only through an injected fake CLI (launch, resolveExecutable, or a fake-only PATH with no AGENTRIX_CODEX_EXECUTABLE and the profile's install folders the test's own, which the helper's Codex search also reads), never the CLI installed on the machine (a test that injects only `launch` also names its `locate`, as the Codex search follows install folders whatever PATH says; the helper's own search runs no `--version`) — results must not depend on the machine — test: `tests/boundary-dispatch.test.cjs` › "dispatch tests start workers only through an injected fake CLI"; test: `tests/dispatch.test.cjs` › "a worker start runs no `codex --version`: the helper locates Codex with a probe that runs nothing"
- A roundtable's working-tree changes invalidate it; unapproved SKILL.md changes are preserved as proposals, restored only inside an isolated worker worktree, and report-only in shared or managed roots or beyond snapshot limits — agreement precedes work and another author's live edits must survive — test: `tests/dispatch-team.test.cjs` › "meetings reject every working-tree change including agreed files"; test: `tests/dispatch.test.cjs` › "dispatch restores unapproved skill edits and reports proposal counts on successful and failed runs"; test: `tests/dispatch-skill-proposals.test.cjs` › "concurrent lead edits in a shared checkout are preserved and reported with unknown authorship"
