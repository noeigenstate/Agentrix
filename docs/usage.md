# Agentrix 使用与开发文档

[返回项目首页](../README.md)

Windows 多项目终端工作台。每个目录对应一个真实终端，Codex 或 Claude Code 的主轮次与项目内所有工作结束后，方框亮起白色呼吸光，点击标题栏全屏查看并继续对话，返回网格后各项目继续运行。

## 使用

从 [Releases](https://github.com/noeigenstate/Agentrix/releases/latest) 下载 Windows `.exe` 即可使用。正式版本在 Releases 中长期保留，普通 CI 构建仍可从 Actions 的 Artifacts 下载。

打包后的应用位于 `release/`。运行 `Agentrix-Setup-<版本>-x64.exe` 安装，获得自动更新功能。从 0.6.12 起不再发布便携版。迁移旧版时，先等任务结束，从设置或托盘退出旧版，再运行安装包。项目列表与会话历史会保留，旧人工完成项目保持停止。

安装版使用独立的 Windows 应用标识，开始菜单登记为 **Agentrix**，可在 Windows 搜索中查找。桌面、任务栏和搜索使用多尺寸的 Agentrix 图标。启动时会修复本应用的快捷方式，并把早期与正式版标识冲突的开发版 Electron 快捷方式备份到应用数据目录；开发和测试窗口不再复用正式版标识。

## 代理

从 0.6.10 起，从桌面图标启动应用时，若进程没有代理环境变量，会读取当前机器的系统代理，并传给本地终端和编码助手。代理地址和端口来自系统设置；已有的 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY` 和 `NO_PROXY`（及其小写形式）会保留。系统没有代理或读取失败时不添加代理变量，读取最多等待 3 秒。终端自己的启动文件仍可设置代理；SSH 远程终端使用远程机器的配置。

## 自动更新

- 安装版启动约 20 秒后自动检查 GitHub Releases，之后每 4 小时检查一次；也可以在设置中手动检查。
- 有新版本时在后台下载，设置中显示当前版本与下载进度；下载完成后，顶部设置图标出现提示点。
- 点击「重启并安装更新」才会退出安装。仍有终端打开时会先确认，取消后可以继续工作，不会强制重启。
- 早期便携版和未安装的解包目录不执行自动更新，设置中提供安装版下载入口。
- 更新使用 Release 中的安装程序、`latest.yml` 和 `.blockmap`，下载后由 electron-updater 校验文件摘要。更新失败可在设置中重试。

## 日常操作

1. 按 **Ctrl+Shift+N** 打开「添加项目」（快捷键可在设置的「键盘快捷键」中修改），选择「本地项目」后选择一个或多个目录；或选择「SSH 远程项目」连接 Linux 主机。「本地项目」下方列出最近打开过、现在未打开的项目（最多 30 个），点击即可重新添加并启动终端；悬停后点 × 从列表删除，「清空」删除全部。文件夹已不存在的项目显示为灰色。「SSH 远程项目」下方同样列出最近连接过、现在未打开的服务器和目录，点击即可重新连接并添加。
2. 新项目的方框里有两个按钮：**Claude Code** 和 **Codex**。上方选「开始新开发」或「继承开发历史」，继承会接上这个文件夹最近的那次对话（按钮下注明上次是什么时候）。其他命令行助手点「只打开终端」后自己运行；终端里也可以照常用 `codex resume` 或 `claude --resume` 挑选更早的对话。若会话仍在其他窗口运行，先在原窗口结束当前会话，再在这里恢复。阅读视图目前支持 Claude Code 和 Codex，之后会陆续支持更多 CLI。
3. Codex 或 Claude Code 的**主轮次、后台子代理与命令、排队消息和项目内其他终端的工作全部结束**后，方框亮起白色呼吸光并显示「等待你查看」，直到查看才熄灭。在终端输入 `claude` 即可让 Claude Code 的每轮对话同样被识别。如果开启桌面通知，后台也会提醒。
4. **点击方框标题栏、右上角等待状态或展开按钮**：方框从原位置逐渐放大进入全屏，并标记本轮已查看。直接在终端里继续输入指令。
5. 点击左侧的 **返回总览**，或按 **Ctrl+Shift+G**，方框平滑缩回网格。按 **Ctrl+Shift+方向键** 按网格位置切换到左、右、上、下的项目（左右到行尾时接上一行或下一行）；总览里只选中方框，放大时直接切换放大的项目。文本框里有文字时，这组键仍用来按词选择。终端进程、未发送的输入和任务继续保留；默认使用平滑缩放，可在设置中选择“跟随系统”或“关闭”。
6. 查看本轮结果后，可直接输入下一条指令；应用结合 Codex、Claude Code 会话轮次和项目内所有工作自动显示状态，不再提供人工完成标记。

每个方框右上角的菜单可以新建终端、打开项目目录、重启终端或移除项目。本地目录通过系统资源管理器打开，SSH 目录在应用内展开。移除项目不会删除项目文件。

安装 MiMo 等命令行工具后，如果安装程序已经把目录加入 Windows PATH，点击项目菜单的 **重启当前终端** 即可识别，无需退出整个 Agentrix。每个新建、重启或重新打开的本地终端都会补入最新的系统/用户 PATH 目录；原有工具链目录保持优先，其他终端保留自己的环境和任务。该行为仅补充本地 PATH，不替换其他环境变量；SSH 继续使用远端 shell 的环境配置。

点击项目标题栏「⋯」菜单里的 **新建终端并分屏**，在同一项目新增独立终端。界面按窗口宽度和终端数量自动排列，每个分屏可以单独运行 Codex 或 Claude Code、语音输入、重启或关闭；分屏之间只有细分隔线，不在方框边缘再画一圈。按住分屏的标题栏可以拖到别的位置，和总览里拖动项目方框一样；终端内容不受影响，标题编号不变，顺序会保存。重开应用后，各个终端恢复各自的 Codex 或 Claude Code 会话；关闭一个分屏不会关闭其余分屏。项目状态优先显示仍在运行的任务，各终端同时显示自己的状态。

状态来自当前交互主会话的轮次记录：任务开始显示「正在处理」，等主轮次、它启动的所有后台子代理与命令、排队消息以及项目内其他终端的工作全部结束后才提醒，中断显示「已中断」。单个步骤、子代理或命令结束，以及过期轮次的通知，都不能单独触发项目完成提醒。恢复历史对话时，不会把上次完成时间当成当前状态；尚未取得轮次记录时显示「Codex 会话中」。本地与 SSH 都增量读取记录，不按终端静默时间或输出关键词猜测完成。

总览中按住项目顶部的标题区域，整个真实方框会悬浮跟随鼠标，其他项目平滑让位并依次排列；松开后落位，顺序自动保存。按 Esc 或拖到网格之外可取消。项目较多时，拖到网格上下边缘可自动滚动。普通点击标题仍进入全屏，终端正文仍用于选字与复制。

普通、等待查看和已完成的项目均通过顶部标题栏或右上角展开按钮放大，使用同一段约 720 毫秒的渐进动画，返回约 560 毫秒。点击终端正文、输入区和底栏不会放大，可留在小窗口中输入、选字和复制。设置里的“窗口放大动画”默认为“平滑缩放”；选择“跟随系统”后才会受系统减少动态效果影响，也可选择“关闭”。

## 麦克风与本地语音输入

首次下载约 64 MB 的语音引擎与多语言模型，之后可离线使用；下载支持续传，不需要 API 密钥。进度可在工作台设置的「本地语音输入」查看。

1. 按 **Ctrl+T**，当前项目方框正中出现话筒，开始对当前终端录音。当前终端依次取：有键盘焦点的终端、全屏项目里选中的终端、最近点过的终端、画面上唯一的终端。
2. 说完按 **回车**（或再按一次 Ctrl+T）：识别后文字插入终端并自动发送。按 **Esc** 取消，什么都不输入。
3. 也可点击终端上的麦克风开始录音：回车同样识别并发送；再次点击麦克风则只插入文字，由你检查后手动发送。

终端显示为文档排版（阅读视图）时，识别出的文字直接出现在底部输入框的光标处；按回车或再按 Ctrl+T 时连同框里已有的文字一起发送。

单次录音最长 5 分钟，到时只插入不发送；隐藏应用会停止麦克风。Ctrl+T 由应用接管，不再传给终端里的程序。

识别使用 [whisper.cpp](https://github.com/ggml-org/whisper.cpp) 和 Whisper Base Q5_1 多语言模型，在本机 CPU 运行。音频不上传，正常识别结束后删除临时录音。下载的引擎和模型由固定 SHA-256 校验；麦克风仅开放给应用主界面，HTML 文件预览不能使用它。

## 文件操作

- 路径显示在「资源管理器」标题旁，完整路径可悬停查看；项目介绍区已收起，让文件列表更靠上。
- 顶部按钮或文件右键菜单可以新建文件、新建文件夹。右键菜单提供复制、粘贴、重命名和删除。
- Ctrl/Shift 点击可多选；Ctrl+C 复制文件、Ctrl+V 粘贴、F2 重命名、Delete 删除。Ctrl+A 选择当前已展开的条目。
- 文件复制使用 Windows 原生文件剪贴板，支持粘贴到电脑其他目录；从 Windows 复制的文件也可以粘贴进项目。同名文件会生成副本，原文件保留。
- 粘贴到选中的文件夹：按 **Ctrl+V** 或 **Shift+Insert**，也可右键选择「粘贴」或点击目录栏的粘贴按钮。点击列表空白处再粘贴会放到项目根目录；空文件夹的占位文字也支持右键粘贴到该文件夹。支持同时粘贴多个文件和文件夹。
- 本地删除会先确认，再移入回收站。SSH 删除会先明确确认，远程文件会永久删除。项目根目录不提供删除和重命名操作。
- SSH 项目支持创建、重命名、删除及双向文件传输。复制远程文件时先下载到本机缓存，完成后可粘贴到 Windows 目录；粘贴本地文件到远程项目时按块上传。传输可以取消；已完成的文件会保留。远程复制不展开符号链接，请选择实际文件。

## SSH 远程项目

1. 在 VS Code Remote-SSH 或 OpenSSH 配置好主机，确保该主机能够正常连接。
2. 点击「添加项目 → SSH 远程项目」，选择主机别名，也可输入 `user@hostname`。
3. 输入远程目录，例如 `/home/dev/my-project` 或 `~/my-project`。可选填一个方便识别的名称，也可粘贴 `vscode-remote://ssh-remote+主机/路径` 地址。
4. 点击「连接并添加」。首次连接确认主机指纹；需要密码或密钥口令时，在认证弹窗中输入。

主机列表沿用 VS Code 的 `remote.SSH.configFile`，未设置时使用 `~/.ssh/config`，并读取 Include 中的主机。连接由 OpenSSH 处理，沿用配置中的 IdentityFile、Port、ProxyJump 等参数。密码仅用于这次认证，不写入项目配置。

远端需要 **Linux、Python 3.6+ 和 Bash**；远端 Bash 中需能找到 `codex`。Git 面板需要远端 Git 2.11 或更高版本。远端的 CLI 读不到这台电脑的剪贴板：在 SSH 项目里粘贴截图时，图片会先放进远端的临时目录（`/tmp/agentrix-images-<用户号>`，一周后清理），再把路径交给助手。同一台主机上的所有终端（同一项目的多个终端，以及这台主机上的其他项目）共用一条 SSH 连接，终端、目录和文件预览都经由它传输，文件按需读取：只认证一次，之后新开的终端不再重新握手、登录或输入密码，几乎立即打开。最后一个终端关闭时连接才断开。远端终端会加载 `~/.bashrc`。连接断开后，项目菜单可重新连接；文件目录外的符号链接不会被预览。

SSH 项目的目录菜单、终端目录链接和 Markdown 目录链接都进入应用内资源管理器。项目列表、SSH 主机别名和路径保存在本机，项目文件与 Codex 对话留在服务器上。

## 自动恢复 Codex 会话

默认开启「启动时恢复工作」，可在设置中关闭。真正退出并重新打开应用后：

- 恢复上次打开的终端及其工作目录；之前运行 Codex 的项目自动恢复该目录最近的交互会话。
- 上一轮明确处于中断状态时，执行 `codex resume 会话ID "继续"`；上一轮已完成或状态不明确时，只恢复会话，不提交新指令。
- 正常退出 shell 的项目保持停止。旧版被人工标记完成的项目会迁移为停止状态，主终端和分屏均不自动恢复；需要时手动启动。普通 shell 命令不会被自动重新执行。
- 从旧版首次升级时，没有终端恢复记录的项目会尝试打开已有对话，不自动发送「继续」。后续启动按新记录恢复。
- 本地与 SSH 项目均支持恢复；SSH 需要重新认证时会弹出认证窗口。只关闭到托盘时，原任务继续运行，不会重新恢复一遍。

恢复基于各主机 Codex CLI 保存的会话记录。未找到可识别的记录但上次仍在运行 Codex 时，使用 `codex resume --last` 交由 CLI 选择最近会话，不创建新对话。

## 开发记忆与技能

同一个项目里，Claude Code 和 Codex 的开发记忆会自动继承。每次在本地项目里打开其中一个，Agentrix 会整理这个文件夹里两个 CLI 做过的每一轮：你提的要求、它最后的回答、改了哪些文件、跑了哪些检查，并告诉新打开的 CLI 在第一次回复前先读。不需要任何操作。

这份记忆保存在 Agentrix 自己的数据目录（`memory` 文件夹），**永久保留在本机**，不写进项目，也不会因为 CLI 清理自己的记录（Claude Code 默认一个月后清理）而丢失。SSH 项目每轮结束时也会记进来。

可以反复用的做法会沉淀成技能，放在项目仓库的 `skills/` 文件夹里（每个技能一个子文件夹，里面一份 `SKILL.md`）。CLI 接到任务时会先看有没有合适的技能照着做；发现新的、以后还会用到的做法时，会新建或更新技能。技能会随仓库提交和推送，所以不能带个人隐私：CLI 被要求只写占位符，Agentrix 也会在 CLI 启动和每轮结束时检查本地项目的 `skills/`，把用户名、个人目录、IP 地址、邮箱、电话、身份证号、密码、令牌和私钥等替换成 `<home>`、`<ip>`、`<email>`、`<secret>` 之类的占位符。

## 复制与粘贴

- 本地项目的文件或文件夹右键菜单最上面是 **打开文件位置**：在本机的文件资源管理器里打开它所在的文件夹并选中它（在空白处右键则打开项目文件夹）；SSH 项目的文件在服务器上，没有这一项。
- 文件或文件夹的右键菜单提供 **复制绝对路径** 和 **复制相对路径**，多选时每行一个路径。资源管理器里的 **Ctrl+Shift+C** 复制绝对路径；相对路径以项目根目录为起点。
- SSH 的绝对路径来自服务器，例如 `/srv/project/src/main.py`，不会混入 Windows 路径。

- 鼠标拖选终端文字后，按 **Ctrl+C** 或 **Ctrl+Shift+C** 复制。未选中文字时，Ctrl+C 仍然中断命令。
- **Ctrl+Shift+A** 全选终端文字；右键「复制全部终端文字」包含当前终端缓冲区中的可回滚历史。缓冲区已淘汰的旧输出无法通过此操作找回。
- **Ctrl+V**、**Ctrl+Shift+V**、**Shift+Insert** 或右键「粘贴」把剪贴板文字送入当前终端，保留终端的多行粘贴处理。
- **Shift+Enter** 在输入中换行，普通 **Enter** 才提交。Windows 终端保留原生 Shift 修饰键，SSH 发送独立的修改回车序列；本地 PowerShell 和远程 Bash 均可编辑多行命令。
- 搜索框、SSH 主机、远程目录和密码框支持常规复制粘贴及右键菜单。
- 某些终端程序启用鼠标控制后，需要按住 Shift 拖选；全选与右键复制全部仍可使用。

## 活动：Codex 与 Claude Code 正在做什么

- **活动栏**：展开项目后显示在终端右侧。点击标题栏上的列表按钮收起或展开，选择会被记住；窗口较窄时自动隐藏。多个分屏终端时显示当前选中的那个。从上到下依次是：
  - **正在处理的任务**：正在处理和排队中的提示。
  - **模型路由**：代理 › 接口 › 模型，下面是思考强度和快速/普通模式。它调用的模型逐条列出，显示正在准备、运行中和审核中的数量；审核轮结束后移除对应调用。接口取自 Codex 记录里的 `model_provider`（自定义的服务显示 `config.toml` 里它的 `base_url` 主机名），Claude Code 则看它设置里的 `ANTHROPIC_BASE_URL`、Bedrock、Vertex 等开关；远程项目的 Claude Code 不显示接口。
  - **上下文长度**：当前对话占用的 token / 模型的上下文窗口，70% 起变黄，90% 起变红。
  - **用量**：本轮和本次对话用掉的 token（输入、缓存命中比例、输出）。两个助手都显示 5 小时和每周额度的已用比例：Codex 的取自它的记录，Claude Code 的取自它自己为 `/usage` 获取并缓存的数据，装了 CodePulse 时取更新的一份（卡片下方写着来源和更新时间）。Codex 还显示每项额度的重置时间。用量卡片会在本轮结束、代理的用量缓存变化和额度窗口重置时自动刷新；窗口已重置但尚未取得新数据时显示「已重置，等待更新」。鼠标停在 token 数字上可看精确数量，停在额度百分比上可看一位小数和更新时间。Claude Code 的「本次对话」从对话的第一条提示算起，很长的对话只读取最近一段记录；本轮起点或对话开头不在记录里时，会说明暂无法统计。
  - **重置额度（仅 Codex）**：Codex 用量卡片底部的按钮和剩余重置次数，支持的本地官方账号通过独立的只读 app-server 查询并自动刷新；未知、失败和不支持会单独提示，不会当成 0。点击后先倒数 10 秒，期间随时可以点「取消」或按 Esc；倒数结束才打开 Codex 的 `/usage`，在里面选择要用的重置并确认。Agentrix 自己不调用重置。没有可用重置时按钮不可点。
- **来源**：Claude Code 的步骤读自它的会话记录（`~/.claude/projects/…/会话.jsonl`），Codex 的读自 rollout 记录（`~/.codex/sessions`）；应用只读取，不注入逐个工具的 hook，因此不影响它们的速度。新的一轮开始时列表清空，只保留最近 200 步。
- **范围与限制**：目前支持本地项目；SSH 项目不显示活动。Codex 把所有调用包在脚本里执行，用 shell 脚本改文件时只能显示「通过命令修改文件」而没有文件名；MCP 工具本身的说明文字无法从记录中得到。

## 文档排版（阅读视图）

终端里运行 Codex 或 Claude Code 时，对话默认按时间轴排版显示：左侧一条竖线，你的每条提示、助手的每段回答和每组工具调用各是线上的一个节点，旁边写着时间（同一分钟内重复的时间颜色更淡）。你的提示和按 Markdown 排好的回答（代码块带「复制」按钮）放在磨砂卡片里，每轮第一段回答上方写明是 Codex 还是 Claude Code；一组工具调用折叠成一个胶囊，写明做了什么，改过的文件以小标签列在上面。还在运行的节点外面有一圈转动的光环，失败的节点标红。卡片较窄时省去时间，只留竖线和节点。真实终端一直在下面运行，底部输入框的内容直接发给它，Enter 发送，Shift+Enter 换行，工作中可点停止按钮中断。

- 点击标题栏的终端图标切换到原始终端，再点一次回到文档排版。这个选择保持到该终端里的程序退出，下次启动 Codex 或 Claude Code 时又默认显示文档排版。
- 在输入框里粘贴图片（Ctrl+V）：图片交给 Codex 或 Claude Code 本身，附在下一条消息上，输入框上方显示已附加几张，点 × 移除；只有图片也可以直接发送。
- 回答里写到的本机图片、HTML 页面和视频（完整路径、反引号里的路径或 Markdown 图片 `![说明](路径)`）直接显示在回答下面；工具写出的图片、网页、Markdown 和视频也以卡片显示在那一组步骤下。点卡片或回答里的文件链接，在当前界面弹窗显示大图、网页、文档或文件夹，Esc、× 或点弹窗外面关闭；不会进入项目页，也不会打开其他程序。SSH 项目的文件通过 SSH 读取。
- Agentrix 启动 Claude Code 和 Codex 时会临时告诉它们「写出完整路径，阅读视图就会显示图片、网页和视频，不要用别的程序打开」（Claude 用 `--append-system-prompt`，Codex 用 `developer_instructions`，不写入配置文件；命令行里你自己给的同类参数优先）。SSH 项目目前只对 Codex 生效。
- 发送斜杠命令或 `!` Shell 命令，会在阅读视图上打开同一个实时终端的大弹窗，直接使用 CLI 的键盘、鼠标、选择和复制。Esc 交给 CLI；只通过标题栏关闭按钮或点击弹窗外面关闭，关闭时不会向 CLI 发键，也不会关闭 CLI 的对话框。切换终端、会话或离开阅读视图时弹窗关闭，终端移回原处。本地 `/resume` 仍打开会话列表，`/clear` 仍清空阅读记录。普通消息发送前若 CLI 尚未回到自己的提示符，会打开终端弹窗，消息保留在输入框里。
- 启动前的确认（信任文件夹、选主题、绕过权限警告、新 MCP 服务器、从摘要恢复、Codex 更新提示）、权限确认和选择题都以弹窗或卡片呈现，点选即可。
- 第一次启动、尚未登录时弹出「登录 Claude Code / Codex」窗口：一键在浏览器打开登录页、复制链接，把浏览器给的授权码或 OpenAI API Key 粘贴进去提交，或复制 Codex 的一次性验证码；成功或出错后按「继续」「取消」。这里输入的内容只交给 CLI，不算作对话消息，也不会显示在任务列表里。
- 新项目卡片上没安装的助手标为「未安装 · 点击一键安装」，点一下用 npm 全局安装后直接启动；没有 Node.js 时先打开它的下载页。

## Git 状态与提交历史

展开项目后点击侧栏底部 **Git 历史**。资源管理器自动收起，原位置显示源代码管理；点击上方「资源管理器」或再次点击「Git 历史」切回文件目录，已展开的文件夹保持不变。

- **未提交更改**：分为已暂存、工作区更改和合并冲突。M 表示修改、A 表示新增、U 表示未跟踪，冲突用 ! 提示。一个文件可以同时存在已暂存和未暂存修改；标题数量按文件去重。
- **已提交历史**：每页 40 条，展示提交说明、作者、短哈希和引用；连线来自实际父提交关系。点开一条记录查看已提交文件；合并提交的文件列表相对第一父提交。
- **文件目录标记**：文件用颜色和字母标识 Git 状态，含变更的父目录显示提示点。历史文件列表仅显示状态。
- **逐块查看与决定更改**：点击更改列表中的文件，右侧显示它的每一处更改（`git diff` 的分块）：去掉的行红色、新加的行绿色，两侧为修改前后的行号。每一处可以单独 **保留**（加入暂存区，等同 `git add -p` 选中）或 **还原**（丢弃这些行的修改，等同 `git checkout -p`，会先确认）；工具栏可以全部保留或全部还原，也可以从这里打开文件编辑。「已暂存」里的文件显示索引相对 HEAD 的更改，可逐块 **取消暂存**；未跟踪文件整体显示为新增，保留即加入暂存区，还原会删除该文件；已删除的文件显示为全部移除，还原即找回。二进制文件和非 UTF-8 文本只提示，不提供逐块操作。
- **分支信息**：显示当前分支及已配置上游的领先／落后数量，不自动执行 fetch。数字反映本机已有的远程引用。
- **刷新**：当前侧栏可见且窗口活跃时约每 3 秒检查工作区，收起侧栏或返回总览后停止轮询。历史在 HEAD 或分支变化、翻页及手动刷新时加载；读取失败会显示错误并降低重试频率。编辑器中的草稿保存到磁盘后才会反映到 Git 状态。

支持本地和 Linux SSH 项目，也支持项目位于仓库子目录和 Git worktree。子目录项目的文件及历史限定在该目录范围。除了逐块保留、取消暂存和还原，其余操作只读：不提交、不切换分支。超时及结果过大时明确提示，避免卡住界面；大量变更分批显示，最多列出 5000 项。

## 项目目录与液态玻璃界面

- 总览页直接展示项目网格，不再占用一整行显示标题、计数和分类筛选。搜索框在顶部窗口栏（按 **Ctrl+Shift+F** 打开）；新建项目、返回项目、全屏和设置收在左上角标志和标题的应用菜单里，顶栏没有设置按钮；网格自动排列，没有布局选择和通知铃铛按钮。桌面通知仍可在设置中调整。
- 项目全屏后才显示当前项目的文件目录，支持逐级展开、折叠全部文件夹、手动刷新，以及窗口活跃时每 3 秒自动刷新。
- 点击左上方目录栏按钮或按 **Ctrl+B** 收起、展开左栏；收起后保留返回总览和 Git 历史的图标入口，终端自动适配宽度。设置统一从左上角的应用菜单进入（点标志和标题，或按 **Ctrl+,**），在展开项目时也可使用。
- 展开状态在同一次运行中按项目保留，整个目录栏是否收起会保存到设置。
- 点击 PNG、JPEG、WebP、GIF 等图片会直接显示画面，可「适应窗口」、查看「原始尺寸」或缩放；透明图片显示棋盘格底色，底部显示像素尺寸。
- 常见图片也按文件头识别，支持没有后缀或后缀错误的 PNG、JPEG、GIF、WebP 等图片，以及 ICO、JFIF 文件。
- 点击视频直接进入播放器，支持播放、暂停、拖动进度、音量和全屏；MP4（H.264）和 WebM 已通过实际播放验证。视频按字节范围读取，拖动进度不需要加载整个文件。编码不受内置播放器支持时，可选择系统播放器。
- 点击 HTML/HTM 会直接渲染页面，可切换「页面／源码」。支持项目内相对路径的图片、CSS、JavaScript 模块和 JSON 数据；HTTPS CDN 资源需要联网。依赖 Vite 等开发服务器的源码页面需要先构建后再预览。
- HTML 在独立来源的隔离框架中运行，可以交互，但不能访问应用的 Node.js 或终端控制接口。预览只提供项目内的网页资源，关闭后访问地址失效。
- 关闭预览或点击「返回终端」可继续操作同一个终端，预览期间任务继续运行。文件被更新后可点击「刷新文件」重新加载。
- 不再设置 1 MiB 文本或 32 MiB 图片、HTML 大小门槛。大文本和 HTML 源码每页读取约 256 KiB，支持上一页、下一页、首页、末页和输入页码跳转；只渲染当前可见行。支持 UTF-8 和带 BOM 的 UTF-16，分页不会截断中文或 emoji。大文件的行号和复制功能针对当前页，图片和网页的实际显示仍取决于可用内存及浏览器解码能力。

文本和代码文件打开后直接进入可编辑状态，不需要点击「编辑」。编辑区左侧显示行号，光标所在行的行号高亮；分段读取的大文件每段从 1 开始编号。按 **Ctrl+S** 或工具栏的 **保存** 写入原文件；设置中的「自动保存」（默认开启）会在停止输入约 1 秒后、切换文件或离开窗口时保存。HTML 点击「源码」即可编辑，保存后可切回「页面」查看结果。文件标签上的圆点表示未保存；切换文件、返回总览、重命名或删除当前文件、退出及安装更新前，会询问保存、放弃或取消。

编辑区支持与 VS Code 相同的编辑快捷键（macOS 上 Ctrl 换成 Cmd）：
- **Ctrl+/**：注释或取消注释选中的各行（没有选中时为光标所在行）。注释符号按文件类型选择：JS/TS/JSON 等用 `//`；Python、YAML、TOML、Shell、`.env`、`.conf`、Dockerfile 等配置文件用 `#`；INI 用 `;`；SQL 用 `--`；HTML、XML、Markdown 和 CSS 没有行注释，整段包进 `<!-- -->` 或 `/* */`。选中各行都已注释时取消注释，否则全部注释。
- **Ctrl+F**：在右上角打开查找栏，文件里所有匹配处都标出来，显示“第几个/共几个”；Enter 下一个、Shift+Enter 上一个（在正文里也可以按 F3 / Shift+F3），Aa 区分大小写；Esc 关闭并回到正文，选中当前匹配。选中一段文字再按 Ctrl+F 会直接查找它。
- **Shift+Alt+A**：给选中的内容加上或去掉块注释。
- **Tab** / **Shift+Tab**：选中多行时整体缩进或减少缩进，也可以用 **Ctrl+]** / **Ctrl+[**。缩进单位跟随文件本身（制表符、2 个或 4 个空格）。
- **Alt+↑/↓** 上下移动所在行；**Shift+Alt+↑/↓** 向上或向下复制所在行；**Ctrl+Shift+K** 删除所在行；**Ctrl+L** 选中整行，连按会继续向下扩展；**Ctrl+Enter** 在下方插入新行。
- 按 **Enter** 换行时保留当前缩进；在 `{`、`[`、`(` 后（Python、YAML 中在 `:` 后）多缩进一级。

每个操作都可以用一次 Ctrl+Z 撤销。代码按文件中的原字符显示，不合并连字（`<!--`、`!=` 不会显示成其他符号）。

Git 项目中，行号旁的彩色竖条表示尚未暂存的改动，与 Git 侧栏的「工作区更改」一致：绿色为新增行、蓝色为修改行，红色小三角表示此处删除了行；已暂存的改动不再标记，Git 尚未跟踪的文件整篇算新增，仍处于合并冲突状态的文件不显示竖条。改动标记在打开文件和每次保存后更新。文件中含有合并冲突（<<<<<<< / ======= / >>>>>>>）时，当前与传入两部分分别用绿色、蓝色底色标出，冲突开头一行右侧有「保留当前更改」「保留传入的更改」「保留双方」三个按钮；不会自动替你选择。点选只是一次普通编辑，可用 Ctrl+Z 撤销，之后与其他修改一样按 Ctrl+S 或自动保存写入文件。右上角会提示还剩几处冲突。

Markdown（`.md`、`.markdown`、`.mdown`、`.mkd`）提供「编辑 / 预览」切换。预览显示当前草稿，支持标题、列表、任务列表、表格、引用、代码块、图片、网页链接和文档内锚点；相对图片和文件链接从文档所在目录解析，也支持 SSH 项目。预览里的脚本和事件属性会被过滤。大 Markdown 文件按当前段预览；切换预览不会自动保存或丢弃修改。

保存会检测文件是否被 Codex 或其他程序修改，遇到冲突保留当前草稿并提示刷新，不直接覆盖较新的文件。大文件按当前段编辑，只替换这一段，其他字节保留；单段编辑内容上限为 1 MiB，文件总大小不受此限制。保存保留 UTF-8 / UTF-16 编码、BOM 与原有换行格式。本地与 SSH 项目均支持。

- 目录按需读取，大目录每页 200 项，可以继续加载；不会预先递归扫描整个项目。项目外的链接目标不在文件预览范围内。
- 设置的「主题」可选「黑底白字」（默认）或「白底黑字」，立即生效并保存；窗口底色、终端配色、单色项目标志、Codex 标志、Git 与编辑器的增删颜色随主题切换，已打开的终端不需要重启。
- 背景使用 macOS 山湖、海岸与暖色山峰壁纸，2560 像素宽的图片随应用离线打包。工具栏、侧栏和终端面板叠加透明玻璃材质，保持清晰文字；遵循系统减少动态和减少透明度偏好。壁纸来源与处理说明见 [background-art.md](background-art.md)。
- 玻璃材质借鉴 Liquid Glass 的层次感：导航、按钮、弹窗采用更圆润的轮廓、双层边缘高光和柔和阴影；终端正文有独立的暗色承托。设置使用胶囊开关，按钮按下与菜单展开有轻量反馈。这是 Windows 应用中的网页材质实现，见 [设计说明](glass-material.md)。
- 新建终端会清除从父进程继承的 `NO_COLOR` 等禁用颜色标记，并启用 truecolor 终端能力，保留 Codex 和其他命令的 ANSI 颜色。旧终端需要在更新后重启才能使用新的环境设置。
- 正文、路径和终端文字使用更明亮的配色，文字区域的玻璃底色加深，减少背景对阅读的影响。
- 终端文字默认用显卡绘制（设置 › 外观 › 终端渲染 › GPU 加速）。Codex 和 Claude Code 工作时每秒重绘界面十次左右，用网页方式逐行排版会占去大部分处理器时间；显卡绘制后，四个助手同时工作时窗口的处理器占用约为原来的四分之一。最多 12 个终端用显卡绘制，其余的和显卡出错（例如从睡眠唤醒）时自动改用兼容方式。如果终端文字显示异常，选择「兼容模式」。
- 按住 **Ctrl + 鼠标左键** 点击终端链接：HTTP/HTTPS 地址交给默认浏览器，项目内文件和文件夹在当前界面弹窗打开，不会进入项目页（项目页已打开时，文件夹在目录栏中展开）。支持普通网址、Markdown 文件链接、OSC 8 超链接、中文路径和终端自动换行的链接；普通单击不打开链接。`art/report.html`、`./art/report.html` 等相对路径自动按对应项目根目录补全，本地和 SSH 项目均适用。Codex 输出的 `报告 (art/report.html)`、方括号包裹的路径，以及文件名中合法的括号均可识别。

外观固定为「海岛暮蓝」（Catalina），仍可在「工作台设置 → 外观」调整材质、玻璃透明度、字号与终端字体。

## 状态

| 外观 | 含义 | 如何改变 |
| --- | --- | --- |
| 无光、无边缘 | 项目终端或助手会话已打开，尚无新完成提醒 | 正常输入命令 |
| 蓝色边缘 | 项目内仍有工作或排队消息 | 等待全部工作结束 |
| 白色呼吸光，无边线 | 所有工作结束，尚未查看，显示「等待你查看」 | 点击标题栏、等待状态或展开按钮查看，或在终端发送下一条指令 |
| 无光、无边缘 | 已查看，状态为「本轮已完成」 | 直接输入下一条指令 |
| 红色边缘 | 终端启动失败或助手异常退出 | 查看真实终端输出，处理后重启 |

待查看状态不会因搜索、窗口失去焦点或关闭到托盘而消失；在该项目的终端里发送新指令即视为已查看，不再显示「几轮未查看」。每次提交新指令后，只接受一次完成提醒；没有新提交时，后台返回不同 thread-id / turn-id 也不会重复提醒。
未查看的完成卡片持续亮起白色呼吸光，光从边缘向终端内部淡入，没有边线，每次呼吸约 2.5 秒，直到查看才停止。查看、切换窗口、终端刷新和重启软件不会重新启用旧提醒；输入但尚未发送的草稿也不会。自动恢复被打断的任务并发送“继续”时，允许新的完成提醒；只打开已完成的历史会话则保持安静。

工作中保留蓝色边缘，出错保留红色边缘；只有全部做完且未查看的卡片才呼吸。已查看后没有光和边缘，状态标签显示「本轮已完成」。项目放大进入专注模式后不画任何边缘。点击标题栏、右上角等待状态或展开图标可进入项目。

**Codex 会话中**表示 CLI 仍在终端里运行，不代表模型在每一秒都在生成。状态只描述当前任务轮次，不再标记整个项目是否开发完成，也不从回复文字推测状态。

## 窗口与保存

- 网格按项目数量自动排列；空间不足时可以滚动，点击任意项目标题即可全屏。
- 默认关闭到系统托盘，任务继续运行；点击托盘图标恢复窗口。
- 真正退出需要从托盘菜单或设置里点击「退出应用」。存在终端时会提示任务将被结束。
- 重新启动应用会恢复目录、未读记录，以及按设置恢复上次的终端和 Codex 会话；旧人工完成项目保持停止，原有可见终端仍可手动启动。
- 数据保存在 `%APPDATA%/Agentrix/workspace.json`，记录项目路径、SSH 主机和恢复状态，不保存密码、终端文字或对话内容。
- 终端回看缓冲区在内存中，每个终端最多约 1 MiB，退出应用后释放。
- 窗口遵循系统减少动态效果偏好，启用时保留红色状态而停止闪烁。

## 安装细节

### macOS 安装

支持 Apple 芯片 Mac（M1 或更新型号）和 macOS 12 或更高版本。GitHub [Releases](https://github.com/noeigenstate/Agentrix/releases/latest) 提供 `Agentrix-<version>-mac-arm64.dmg`、`Agentrix-<version>-mac-arm64.zip` 和校验文件 `SHA256SUMS-mac.txt`。

推荐在终端运行以下命令安装，更新时也用同一条命令：

```bash
curl -fsSL https://raw.githubusercontent.com/noeigenstate/Agentrix/main/scripts/install-macos.sh | bash
```

脚本下载最新版本的 ZIP，验证 SHA-256 校验和，安装到 `/Applications`（该目录不可写时改用 `~/Applications`），然后打开应用。无需管理员密码；`curl` 下载的文件不带隔离标记，因此打开时不会出现 Gatekeeper 提示。**macOS 版不会自动更新**，再次运行安装命令即可更新。

可以在管道后的 `bash` 前设置这些变量：

- `AGENTRIX_VERSION=1.3.5`：安装指定版本。
- `AGENTRIX_INSTALL_DIR=~/Applications`：指定安装目录。
- `AGENTRIX_OPEN=0`：安装后不打开应用。

例如，安装 1.3.5：

```bash
curl -fsSL https://raw.githubusercontent.com/noeigenstate/Agentrix/main/scripts/install-macos.sh | AGENTRIX_VERSION=1.3.5 bash
```

如果已经下载了 ZIP，也可以用本地的安装脚本安装：

```bash
bash install-macos.sh ~/Downloads/Agentrix-1.3.5-mac-arm64.zip
```

应用使用临时签名（ad-hoc），没有 Apple Developer ID，也未经过 Apple 公证。如果用浏览器下载 DMG，再将应用拖到「应用程序」，首次打开时 macOS 会提示「无法验证开发者」。在「系统设置 › 隐私与安全性」中点一次「仍要打开」，或运行：

```bash
xattr -dr com.apple.quarantine "/Applications/Agentrix.app"
```

### macOS 终端与快捷键

本地终端以登录 shell 方式运行 zsh（`/bin/zsh`），照常加载你自己的 `~/.zshenv`、`~/.zprofile`、`~/.zshrc` 和 `~/.zlogin`。Agentrix 在此基础上加入提示符状态报告和 `codex` / `claude` 包装层，支持轮次状态、Claude Code hooks、完成提醒和会话恢复，不修改任何用户文件。你为 `codex` 或 `claude` 定义的别名仍然有效。SSH 项目的用法与 Windows 相同。

终端中用 `⌘C` / `⌘V` / `⌘A` 复制、粘贴和全选，`Control+C` 中断命令，`⌘+点击`打开链接。`⌘Q` 退出（终端仍在运行时会先询问），`⌘H` 隐藏，`⌘M` 最小化。设置里的项目快捷键仍默认使用 Control，例如 `Control+Shift+N` 添加项目。

放大项目只会在当前窗口内展开，不会切换到全屏空间（Space）。需要全屏时，使用窗口的绿色按钮或全屏快捷键。

### Linux 安装

支持 x64 和 arm64。GitHub [Releases](https://github.com/noeigenstate/Agentrix/releases/latest) 提供 `Agentrix-<version>-linux-x86_64.AppImage`、`Agentrix-<version>-linux-arm64.AppImage`、同内容的 `.tar.xz` 压缩包，以及校验文件 `SHA256SUMS-linux-x64.txt` / `SHA256SUMS-linux-arm64.txt`。

推荐用 AppImage，下载后无需安装：

```bash
chmod +x Agentrix-*-linux-*.AppImage
./Agentrix-*-linux-*.AppImage
```

也可以用 `tar -xJf` 解压 `.tar.xz`，运行其中的 `./agentrix`。Ubuntu 23.10 及更新版本默认禁止未登记的程序使用 Chromium 沙箱所需的用户命名空间，这时运行压缩包里的程序要加上 `--no-sandbox`；AppImage 会自动检测并处理。**Linux 版不会自动更新**，下载新版本替换即可。

### Linux 终端与快捷键

本地终端可在「设置 › 终端与编辑 › 终端」中选择 Bash 或 zsh，默认跟随你的登录 shell（`$SHELL`）。没装 zsh 时只能选 Bash。Bash 与普通终端一样读取 `/etc/bash.bashrc`（如有）和你自己的 `~/.bashrc`；zsh 照常加载 `~/.zshenv`、`~/.zprofile`、`~/.zshrc` 和 `~/.zlogin`。Agentrix 在此基础上加入提示符状态报告和 `codex` / `claude` 包装层，支持轮次状态、Claude Code hooks、完成提醒和会话恢复，不修改任何用户文件；你为 `codex` 或 `claude` 定义的别名仍然有效。SSH 项目的用法与 Windows 相同。

快捷键与 Windows 一致：终端里选中文字后 `Ctrl+C` 复制（或 `Ctrl+Shift+C`），`Ctrl+V` 粘贴，`Ctrl+Shift+A` 全选，没有选中时 `Ctrl+C` 中断命令，`Ctrl+点击`打开链接。目录栏的文件可以和系统文件管理器（Files、Dolphin、Thunar 等）互相复制粘贴；读取剪贴板时优先使用已安装的 `wl-paste` 或 `xclip`。

## 运行条件与范围

- Windows 10/11 x64（本地终端为 Windows PowerShell 或命令提示符，基于 ConPTY）；Apple 芯片 Mac，macOS 12 或更高（zsh）；64 位 Linux 桌面，x64 或 arm64（Bash 或 zsh）。
- Codex CLI 或 Claude Code 至少一个已安装并在 PATH 中；当前在 Codex CLI 0.162 与 Claude Code 2.1.294 上验证。
- 支持标准 npm 安装和原生 `codex.exe`。
- 本应用为所选目录创建独立终端。VS Code 中已经运行的终端不会被直接搬入这个窗口。
- 完成检测适用于本应用本地终端或 SSH 项目 Bash 中的 `codex` 函数，包括 `codex resume`。直接运行绝对路径可执行文件、自定义别名或在终端里另行嵌套 SSH/WSL 不会自动接入。
- 首版使用 Codex 的 `notify` 参数，覆盖当前这一条 Codex 命令的通知程序；**不改写全局 Codex 配置**。已有自定义 `notify` 程序不会同时执行。用户手动传入 `-c notify=...` 会覆盖本应用的检测。
- 普通命令结束、终端退出、长时间无输出、回复里出现「完成」等情况都不会单独触发项目完成提醒。
- 本版提供项目网格、完整终端、文件目录、图片查看、视频播放、HTML/Markdown 渲染及大文本分段编辑；文件在应用内打开、编辑和保存。

## 本地开发

```powershell
npm install
npm start
```

`npm start` 构建并打开桌面窗口；`npm run dev` 开启 Vite 开发服务与 Electron。

```powershell
npm run build
npm test
npm run test:desktop
npm run test:sessions
npm run test:workspace
npm run test:motion
npm run test:completion
npm run dist
```

- `build`：TypeScript 检查和前端构建。
- `test`：状态持久化、事件传输、终端环境、目录与大文本分页、Unicode 边界、图片识别、视频字节范围、链接解析及预览访问边界测试。
- `test:desktop`：真实终端和按钮交互、通知、目录、PNG 显示/缩放/刷新、HTML/CSS/脚本加载与隔离、视频播放/暂停/跳转/全屏、大文本翻页、Ctrl 单击普通与 OSC 8 链接，以及窄窗口检查。不会向模型提交编码任务，不会修改日常工作区设置。截图在 `.test-output/desktop-*/`。添加 `-- --packaged` 可检查打包后的应用。
- `dist`：生成 Windows x64 NSIS 安装程序、`latest.yml`、`.blockmap` 和 `win-unpacked`。
- `test:sessions`：用离线 Codex 替身验证两次启动恢复；检查输入框粘贴、终端复制/粘贴、SSH 认证弹窗和远程媒体预览。SSH 服务只监听本机随机端口，不连接日常远程主机。添加 `-- --packaged` 可检查打包版。
- `test:workspace`：实际文件新建/重命名/删除、Windows 文件剪贴板与资源管理器粘贴，并用模拟麦克风测试检测、录音、编辑和插入。默认仅替换识别后端以便 CI 离线运行；传入 `-- --voice-assets 路径` 可使用真实 Whisper 引擎和模型测试全流程。资源目录需包含 `runtime/Release/whisper-cli.exe` 及 `ggml-base-q5_1.bin`。测试不使用真实麦克风，不向模型提交编码任务。
- `test:motion`：检查真实卡片展开、缩回的中间尺寸、快速反向切换、窗口尺寸变化和减少动态效果，并验证同一终端及未发送输入得以保留。截图在 `.test-output/focus-motion-*/`，支持 `-- --packaged`。
- `test:completion`：通过离线 Codex 进程、主会话轮次记录和真实 PowerShell 通知钩子验证运行、完成、中断，检查子会话通知、旧轮次、草稿和重启不会误报完成。系统通知会被测试计数器替代，不打扰日常工作区，支持 `-- --packaged`。
- `test:editor-terminals`：验证本地与 SSH 路径复制、文本/HTML 保存、外部修改冲突、未保存导航与退出，以及同项目独立终端、自动分屏、各自恢复会话和关闭一个后保留另一个。截图在 `.test-output/editor-terminals-*/`。
- `test:themes-markdown`：验证海岛暮蓝壁纸离线加载与重启后的固定外观、终端颜色、会话与草稿；检查自动编辑及本地/SSH Markdown 的渲染、保存、相对资源、链接和脚本过滤。
- `test:git`：在隔离配置与 Git 仓库中验证目录标记、已暂存／工作区更改、提交合并关系、提交文件、自动刷新和失败退避、目录收起、未保存保护及本地／SSH 切换。支持 `-- --packaged`，截图与结果在 `.test-output/git-*/`。
- `node scripts/verify-update-artifacts.cjs`：校验安装包、SHA-512、更新清单和应用内置更新源。
- `node scripts/linux-smoke.mjs [--packaged] [--shell zsh]`：在 Linux 上以隔离配置和独立 HOME 启动应用，验证 Bash 或 zsh 终端、Codex 开始与结束状态、`Ctrl+Shift+C` 复制和 `Ctrl+C` 中断；`node scripts/appimage-smoke.mjs <AppImage>` 启动 AppImage，确认终端环境不含 AppImage 的目录和变量。
- `node scripts/verify-installer-payload.cjs`：从实际 NSIS 安装包提取程序，核对可执行文件与应用资源；动画检查可用 `node scripts/focus-motion-smoke.mjs --executable 路径` 直接验证提取出的程序，不添加专用渲染开关，并清除测试工具默认的动态效果模拟，使用真实 Windows 偏好。

终端依赖锁定为 `node-pty@1.2.3-beta.15`，使用其随包提供的 ConPTY 1.25，修复旧版在窗口缩放后光标坐标不同步的问题。相关上游说明见 [microsoft/terminal#18725](https://github.com/microsoft/terminal/issues/18725)。渲染端同步启用光标所在行的重排，并在预览期间保持终端布局。

## GitHub 自动构建

[Windows 构建工作流](https://github.com/noeigenstate/Agentrix/actions/workflows/build-windows.yml) 使用 GitHub 托管的 `windows-latest` runner，无需配置单独的 webhook 服务。

- 推送到 `main`、推送 `v*` 标签、提交面向 `main` 的 PR，或在 Actions 页面点击 **Run workflow** 都会触发。
- 流程：`npm ci` → 单元测试 → 生成 Windows 安装版 → 校验自动更新文件 → 打包版桌面测试 → 上传可执行文件和 SHA-256 校验信息。
- 独立的 Ubuntu job 使用真实 OpenSSH 连接测试服务，运行 Linux Python worker、Bash PTY、文件读取与 Codex 通知测试；发布前必须同时通过 Windows 和 Linux 检查。
- Linux 桌面版在 `ubuntu-24.04`（x64）和 `ubuntu-24.04-arm`（arm64）上构建：单元测试（含真实 Bash 和 zsh 终端）→ 生成 AppImage 与 tar.xz → 检查包内容 → 在虚拟显示器中用打包版分别验证 Bash 与 zsh 终端和 Codex 状态 → 检查 AppImage 的终端环境，产物为 **Agentrix-linux-x64** 和 **Agentrix-linux-arm64**。
- 桌面回归测试会实际点击「只打开终端」，覆盖网格和全屏，确认按键不被遮挡，再检查真实 PowerShell 与 Codex CLI 启动。
- Codex 检查只运行版本和配置命令，不调用模型，不需要 API 密钥或 ChatGPT 登录。
- 构建通过后，在对应运行的 **Artifacts** 中下载 **Agentrix-windows-x64**，解压后双击 `.exe`。产物保留 30 天；测试截图保留 7 天。
- 推送与 `package.json` 一致的版本标签（如 `v0.3.0`）时，构建与测试通过后会自动创建 GitHub Release，附上两个 `.exe`、`latest.yml`、`.blockmap`、macOS 的 DMG 与 ZIP、Linux 两种架构的 AppImage 与 tar.xz、SHA-256 校验文件和构建信息；普通 `main` 推送只生成 Artifacts。
- 发布任务会重新校验下载产物，只为发布阶段申请仓库写权限。已发布的版本不会被重跑任务覆盖；预发布版本会标为 prerelease。
- GitHub Packages 面向 npm、NuGet、容器等软件包；本项目以 Windows 可执行文件交付，下载入口是 Releases。

发布新版本时，先提交代码，再执行：

```powershell
npm version patch
git push origin main --follow-tags
```

版本标签必须与 `package.json` 的版本一致，否则工作流会停止发布。

终端使用 xterm.js + node-pty，主进程使用 Electron。渲染器禁用 Node 集成并开启隔离和沙箱，通过限定 IPC 访问终端。完成通知通过每次运行随机命名的本地管道发送，并校验独立终端的会话令牌。前端资源全部随应用打包。
